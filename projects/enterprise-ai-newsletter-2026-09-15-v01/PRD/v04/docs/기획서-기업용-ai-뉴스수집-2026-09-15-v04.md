# 기획서: 기업용 AI·업무자동화 HTML 뉴스레터

작성일: 2026-09-15
버전: v04
작성자: 김솔지 / 관심 직무: AI 솔루션·업무자동화 개발자

## 1. 풀고자 하는 문제와 목표

기존 뉴스레터는 분석 7건이 이어져 읽는 부담이 크고, 핵심 문장과 제목의 단계가 잘 구분되지 않는다. 마크다운 문서는 보는 프로그램에 따라 표시도 달라진다.

직무·산업 분석 3개와 가벼운 AI 읽을거리 2개, 총 5개를 브라우저에서 읽는 HTML 뉴스레터로 만든다. 핵심 문장과 제목 구조를 눈에 띄게 표시하면서, 상세 분석의 근거와 직무 연결은 유지한다.

직무는 기업의 업무를 분석하고 기존 시스템·데이터와 AI를 연결해, 사람이 확인할 수 있는 자동화 시스템을 만들고 운영하는 역할로 이해한다. 어떤 문제를 왜 해결하는지, 실제 구현 과정과 필요한 기술·업무·소통 역량을 함께 다룬다.

## 2. 사용자와 입력

- 사용자: 기업용 AI·업무자동화 분야로 진로를 준비하는 본인.
- 관심 직무: AI 솔루션·업무자동화 개발자, AI Integration Engineer, Enterprise AI Solution Engineer.
- 기존 경험 연결: Java 운영개발, 시스템 분석, 장애 대응, 데이터베이스·API 연결, 운영 부서 협업.
- 공통 기준: 관심 산업·직무, 본 기획서와 기존 직무조사 자료. 이번 재작성의 사실 근거는 승인한 검증 자료 묶음이다.
- 새 수집: 실행일 기준 달력상 최근 3개월. 예를 들어 2026-09-15 실행이면 2026-06-15~2026-09-15를 포함한다.
- 재작성: 사용자가 지정하거나 가장 최근에 승인한 `research-pack-YYYY-MM-DD-vNN.md`.
- 언어: 한국어. 해외 자료도 쉽게 풀어 쓰고 전문용어는 첫 등장에 설명한다.
- 개수: 원문 자료 1건을 콘텐츠 1개로 센다. 분석 3개 + 읽을거리 2개, 총 5개. 같은 원문을 두 코너에 중복 사용하지 않는다.
- 지역: 국내 중심으로 해외 관점도 포함한다. 기존 7건 기준의 국내 5건·해외 2건 할당은 적용하지 않고 실제 건수·비율을 표시한다. 새 고정 비율은 별도로 정하지 않았다.

## 3. 이번에 반영하는 수정 목록

### 1) 불필요한 실행 정보 제외

기존 검증 자료 재작성일 때 뉴스레터에서 `인터넷 검색·원문 재확인: 하지 않음` 표시 항목을 제외한다. 실행 방식, 사용한 검증 자료 링크, 원래 검색 기간과 원문 확인일은 유지한다. 검색 없이 재작성하는 내부 규칙과 작업일지 기록은 유지한다.

### 2) 핵심 한 줄 강조

기사 제목 아래에 옅은 배경과 경계선이 있는 핵심 상자를 둔다. `💡 핵심 한 줄` 표시와 요약 문장을 별도 줄로 나누고, 요약 문장 전체를 굵게 표시한다. 위아래 여백으로 본문과 구분한다.

### 3) 제목 단계 구분

| 단계 | 표시 | HTML 구조 |
|---|---|---|
| 뉴스레터 제목 | 페이지의 가장 큰 제목 | h1 |
| 분야·코너 | 산업 동향, 기업 적용 사례, 쉬어가는 AI 이야기 등 | h2 |
| 기사 제목 | 01. 기사 제목 | h3 |
| 분석 영역 | ■ 무슨 일이 있었나 | h4 |
| 세부 질문 | • 어떤 업무 문제를 해결하려 했는가? | 굵은 본문 |

기사 순번에만 숫자를 사용한다. 제목 크기는 상위 단계가 더 크도록 하고, 분석 영역 위에는 충분한 여백을 둔다. 360~390px의 좁은 화면에서도 계층과 줄바꿈을 유지한다.

### 4) 분석 3개 + 가벼운 읽을거리 2개

배치 순서는 분석 2개 → 읽을거리 1개 → 분석 1개 → 읽을거리 1개로 한다.

- 분석: 산업 동향, 기술·제품 동향, 기업의 AI·업무자동화 적용 사례, 기업 기술개발 사례, 기업 공식 기술 콘텐츠에서 선정한다.
- 읽을거리: 흥미로운 AI 이야기·연구·실험, 일상 활용 또는 작은 실습 제안으로 구성한다. 호기심 질문 → 쉬운 이야기·일상 비유 → 기억할 한 줄 흐름을 쓴다.
- 읽을거리는 약 400~700자를 기준으로 하되 출처와 사실의 한계를 생략하지 않는다. 기존 4개 분석 영역·8개 질문은 강제하지 않는다.
- 검증 자료 안의 사실을 새로운 이야기로 풀어쓸 수 있다. 실제로 하지 않은 실험이나 사용자 반응을 지어내지 않고, 직접 해보기는 제안임을 표시한다.
- 참고 뉴스레터는 문체·구성 참고이며 새로운 사실의 근거로 사용하지 않는다. 참고 글의 2025-10-21 발행일은 이번 수집 기간 밖이다.

### 5) HTML 결과물로 전환

최종 뉴스레터를 UTF-8 인코딩의 단일 HTML 파일로 만든다. HTML은 브라우저가 글의 구조와 모양을 표시하는 문서 형식이다. 스타일은 파일 안에 넣고 외부 글꼴·스크립트·이미지에 의존하지 않는다. 읽기 순서, 제목, 링크를 키보드로도 확인할 수 있게 한다.

이번에는 상세 분석을 모두 펼쳐 표시한다. 본문 축약과 버튼을 눌러 아래 내용을 펼치는 더 읽기 기능은 다음 단계로 분리한다. 기존 마크다운 결과물과 검증 자료를 보존한다.

## 4. 분석 기사 3개의 필수 내용

각 분석 기사는 핵심 한 줄, 기업·발표일·지역·출처 유형·원문 링크를 먼저 보여준다. 다음 4개 영역 안에 8개 질문의 답을 모두 표시하고, 마지막에 직무 학습 포인트를 둔다. 확인할 수 없는 답도 생략하지 않고 `확인되지 않음`이라고 표시한다.

### ■ 무슨 일이 있었나

- 어떤 기업에서 무슨 일이 있었는가?
- 어떤 업무 문제를 해결하려 했는가?

### ■ 어떻게 구현했나

- AI가 어떤 시스템·데이터와 연결됐는가?
- 무엇이 자동화됐고 무엇은 사람이 확인하는가?

### ■ 근거가 있는가

- 실제 성과를 보여주는 근거가 있는가?

### ■ 나의 직무와 어떻게 연결되는가

- AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?
- 나의 기존 경험과 연결되는 역량은 무엇인가?
- 더 공부하거나 직접 만들어볼 것은 무엇인가?

전체 종합은 분석 3건을 중심으로 업무 문제, 시스템·데이터 연결, 사람 검토 지점, 필요한 역량과 다음 학습 제안을 정리하고 해당 기사로 연결한다. 도입부 개편이나 실습을 하나로 줄이는 별도 제안은 이번 수정에 포함하지 않는다.

## 5. 실행 방식과 출처 기준

### 새 자료 수집

- 최근 3개월 자료를 검색하고 공식·연구 출처부터 원문을 확인한다.
- 최종 5건 + 예비 최대 2건, 최대 7건만 깊게 검증한다. 부족한 코너·분야·지역의 보충 검색은 한 번만 한다.
- 날짜·핵심 성과가 불명확하거나 자료가 충돌할 때만 보조 출처로 교차 확인한다.
- 검증 자료 묶음(.md)과 뉴스레터(.html)를 같은 새 버전 폴더에 저장한다.
- 실제 수집 시작·검증 완료 시각과 소요 시간을 기록한다.

### 기존 검증 자료 재작성

- 승인한 검증 자료 묶음만 사실의 기준으로 사용하고 인터넷 검색·원문 재확인을 하지 않는다.
- 기존 7건 묶음에서도 5건을 골라 분석 3개·읽을거리 2개로 재구성할 수 있다. 새 주제에 필요한 사실이 없으면 검색으로 전환할지 먼저 확인한다.
- 검증 자료 묶음은 수정하거나 복제하지 않고 새 HTML 뉴스레터만 저장한다.
- 원래 수집 기간과 원문 확인일을 보존하고 현재 다시 검증한 최신 뉴스처럼 쓰지 않는다.
- 재작성 시간과 로컬 검증 결과를 기록한다. 원문 링크의 현재 접속 상태는 재확인하지 않는다.

### 공통 신뢰 기준

정부·공공기관·국제기구, 대학·연구기관, 기업 공식 홈페이지·기술 문서·보도자료·공식 영상, 작성자·발표일·원문을 확인할 수 있는 언론 자료를 사용한다. 채용·중복·출처 불명·확인할 수 없는 원문·광고만 있는 자료는 제외한다. 읽을거리에도 같은 출처·날짜·사실 확인 기준을 적용한다.

기업의 성과 수치는 `기업 공식 발표 기준`으로 표시한다. 개발자 역할 등 해석은 `직무 관점의 해석`으로 구분하고, 확인되지 않은 시스템 연결이나 승인 절차를 추측하지 않는다. 문장은 새로 쓰고 긴 원문을 복제하지 않는다.

## 6. 저장 경로와 이번 실행

실행 전 입력, 검색 여부, 기간, 3개+2개 구성, 예상 분량과 정확한 새 파일 경로를 보여준다. 이미 승인받은 범위는 반복해서 승인받지 않는다. 새 버전 번호가 충돌하면 덮어쓰지 않고 새 경로를 확인한다.

```text
projects/enterprise-ai-newsletter-2026-09-15-v01/
├─ PRD/v04/docs/기획서-기업용-ai-뉴스수집-2026-09-15-v04.md
├─ docs/00-latest.md
└─ newsletters/v04/newsletter-2026-09-15-v04.html
```

- 이번 입력: `newsletters/v02/research-pack-2026-09-15-v02.md`.
- 이번 방식: 기존 검증 자료 재작성. 2026-06-15~2026-09-15 자료, 원문 확인일 2026-09-15.
- 분석 3개: LG CNS의 ERP 테스트, 포스코DX의 사전결산 위험 점검, HPE Zerto의 장애 대응.
- 읽을거리 2개: 삼성SDS AI 활용 조사, SK AX의 업무 맥락·시스템 연결 해설.
- 실제 지역 구성: 국내 4개·해외 1개. 출처 유형은 기업 공식 발표 2개·기업 공식 기술 콘텐츠 3개.
- 스킬 위치: `.agents/skills/enterprise-ai-newsletter/`.
- 최신 기획서 링크는 `docs/00-latest.md`에서 v04를 가리키게 한다. 과거 PRD와 뉴스레터는 이동·수정하지 않는다.

## 7. 완료 조건과 검증

- 총 5개가 분석 3개·읽을거리 2개로 구분된다.
- 핵심 한 줄 5개가 별도 상자 안에서 굵게 보인다.
- 분석 3개에 4개 영역, 질문 8개의 답이 각각 있다. 읽을거리에는 이 형식을 강제하지 않는다.
- 제목 기호·크기·여백이 단계별로 다르고 한글이 깨지지 않는다.
- 출처 5개와 발표일이 검증 자료와 일치하고 새 사실·성과를 추가하지 않는다.
- 재작성에서 검색 미실시 표시 항목은 없고 입력 자료 링크·기간·확인일은 있다.
- 실제 HTML 화면, 좁은 화면의 줄바꿈, 내부 이동과 키보드 접근을 확인한다.
- 자동 검사와 화면 확인, 참가자 확인을 각각 구분해 작업일지에 기록한다.
- 기존 v01~v03과 입력 검증 자료를 보존한다.
