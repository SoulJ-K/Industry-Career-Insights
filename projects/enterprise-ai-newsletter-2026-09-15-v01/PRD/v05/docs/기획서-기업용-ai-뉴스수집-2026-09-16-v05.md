# 기획서: 기업용 AI·업무자동화 HTML 뉴스레터

작성일: 2026-09-16
버전: v05
작성자: 김솔지 / 관심 직무: AI 솔루션·업무자동화 개발자

이 문서는 앞으로 제작할 뉴스레터의 기준이다. 이번 작업은 기획서 갱신과 스킬 기준 대조이며, 새 자료 조사나 뉴스레터 제작 완료를 뜻하지 않는다.

## 1. 문제와 목표

정보와 상세 분석이 처음부터 길게 이어지면 읽는 부담이 크다. 직무에 도움이 되는 내용과 함께 재미있게 쉬어 갈 이야기, 원하는 것을 명확히 말하는 연습이 필요하다.

**직무·산업 분석 2개 + 가벼운 읽을거리 2개 + 생각 정리 연습 1개**, 총 5개 코너를 단일 HTML 뉴스레터로 만든다. HTML은 브라우저에서 글의 구조와 모양을 표시하는 문서 형식이다. 핵심은 짧게 읽고, 관심 있는 직무 글은 같은 화면에서 더 읽기를 펼쳐 근거와 상세 분석을 확인한다.

직무는 기업의 업무를 분석하고 기존 시스템·데이터와 AI를 연결해, 사람이 확인할 수 있는 자동화 시스템을 만들고 운영하는 역할이다. 기술 설명과 함께 업무 문제, 실제 근거, 사람의 판단 지점과 다음 학습을 다룬다.

## 2. 사용자와 공통 기준

- 사용자: 기업용 AI·업무자동화 분야로 진로를 준비하는 본인.
- 관심 직무: AI 솔루션·업무자동화 개발자. 영어 직무명으로는 AI Integration Engineer, Enterprise AI Solution Engineer에 해당한다.
- 기존 경험 연결: Java 운영개발, 시스템 분석, 장애 대응, 데이터베이스·API 연결, 운영 부서 협업. API는 서로 다른 프로그램이 정보를 주고받는 연결 방식이다.
- 언어: 친근한 한국어. 해외 자료도 쉽게 풀고 전문용어는 처음 등장할 때 설명한다.
- 뉴스 원문은 목표 4건이다. 같은 원문을 두 기사로 세지 않는다. 연습 1개와 연습 참고 자료는 뉴스 건수·국내외 비율·뉴스 출처 유형 집계에서 제외한다.
- 지역: 국내 중심으로 해외 관점도 포함하되 고정 할당은 두지 않는다. 실제 선정 뉴스 건수를 분모로 국내외 건수와 비율을 표시하고 출처·기업을 분산한다.
- 새 뉴스 수집 기간: 실행일을 끝으로 달력 기준 최근 3개월. 예를 들어 2026-09-16 실행이면 2026-06-16~2026-09-16을 포함한다. 발표일과 사건 발생일을 구분하고 과거 사례를 재소개하면 회고 자료로 표시한다.
- 재작성 입력: 사용자가 지정하거나 가장 최근 승인한 검증 자료 묶음. 원래 수집 기간·확인일·미확인 사항을 보존한다.
- 기준에 맞는 자료가 부족하면 억지로 채우지 않고 실제 구성과 부족 이유를 밝힌다.

## 3. 이번 수정사항 1~4번

### 1) 직무 2개 + 읽을거리 2개 + 생각 정리 연습 1개

배치 순서는 **직무 분석 → 엉뚱한 AI 실험 → 직무 분석 → 웃기고 공감되는 이야기 → 🧩 생각 정리 연습**이다. 코너 순번은 01~05이며 뉴스 원문은 4건이다.

직무 분석은 산업·기술·제품 동향, 기업의 AI 적용·기술개발 사례, 공식 기술 콘텐츠 중 업무자동화 또는 시스템 연결을 구체적으로 보여주는 자료를 선정한다.

### 2) 읽을거리를 재미 중심으로 변경

- **엉뚱한 AI 실험 1개:** 의외의 실험 목적, 예상 밖 행동이나 결과처럼 호기심을 끄는 소재.
- **웃기고 공감되는 이야기 1개:** 일상에서 AI를 사용하며 생기는 공감되는 상황이나 예상 밖 경험.
- 기술·제품 소개만으로 두 유형을 대체하지 않는다. 원문에서 확인한 재미 포인트를 한 문장으로 설명할 수 있어야 한다.
- 재미있는 상황 → 예상 밖 지점 또는 공감 포인트 → 기억할 한 줄의 흐름으로 쓴다. 직무 연결은 필요할 때 한 줄로 충분하며 직무 분석 질문 8개를 강제하지 않는다.
- 실제 실험·사용자 반응·후기를 지어내지 않는다. 개인 경험은 작성자가 보고한 사례로 한정하고 일반화하지 않는다. 가정·비유·직접 해보기 제안은 사실과 구분한다.
- 문체 참고 뉴스레터의 문장이나 독특한 표현을 복제하지 않는다. 문체 참고 자체를 새 사실의 근거로 사용하지 않는다.

### 3) 🧩 생각 정리 연습 추가

원하는 결과, 조건과 판단 기준을 구체적인 말로 정리하는 연습이다. 한 호에는 목표 구체화, 사실과 추측 구분, 비교 기준 세우기, 빠진 조건 찾기 중 하나만 다룬다.

- 형식: 짧은 상황 하나 → 직접 생각해볼 질문 2~3개 → 생각의 예시.
- 상황과 질문은 먼저 표시하고 예시는 기본적으로 접어 둔다. `생각의 예시 보기`를 누르면 아래에 나타나며 `예시 접기`로 다시 접는다.
- 예시는 유일한 정답이 아니다. 목표·조건·판단 기준을 정리하는 과정을 보여주고, 필요하면 AI에게 전달할 요청문을 한 문장 제안한다.
- 직접 만든 상황은 `연습용 가상 상황`이라고 표시한다. 연습 목표와 참고 개념·출처 링크는 접지 않고 표시한다. 출처가 만든 문제처럼 표현하지 않는다.
- 참고 개념 자료는 대학·교육기관·공공기관 또는 작성 주체가 명확한 원저자의 교육·연구 자료에서 1건을 목표로 확인한다.
- **개념 참고 자료에는 최근 3개월 제한을 적용하지 않는다.** 원래 발표·수정일과 확인일을 기록하고 날짜가 없으면 미표기로 밝힌다. 최근 사건을 소재로 쓰면 뉴스와 같은 기간·원문 확인 기준을 적용한다.
- 연습 효과나 논리적 사고·AI 활용 능력 향상을 검증 없이 보장하지 않는다.

### 4) 본문 축약 + 더 읽기 펼치기·접기

| 영역 | 처음 보이는 내용과 목표 분량 | 펼쳤을 때 |
|---|---|---|
| 직무 분석 2개 | 무슨 일인가 → 왜 중요한가 → 내 직무와의 연결, 짧은 3문단·250~400자 | 4개 영역·필수 질문 8개의 답과 직무 학습 포인트 |
| 가벼운 읽을거리 2개 | 짧은 재미 이야기·250~450자 | 추가 맥락이 꼭 필요할 때만 상세 제공 |
| 생각 정리 연습 1개 | 상황·질문·200~350자 | 생각의 예시·150~300자 |

분량은 공백 포함 기준이다. 제목·핵심 상자·출처와 접힌 상세는 기본 본문 분량에서 제외하며, 정확성이 우선이다. 상세 답은 질문당 1~3문장을 기본으로 한다.

- 직무 분석의 조작부는 닫혔을 때 `더 읽기 · 상세 분석`, 열렸을 때 `접기 · 상세 분석`으로 표시한다.
- 클릭하면 해당 글 바로 아래에 상세가 나타나고 같은 조작부로 다시 접힌다. 다른 글의 펼친 상태는 유지한다. 페이지 이동·팝업·새 창 방식은 사용하지 않는다.
- 출처와 핵심 한계(기업 주장, 실험 단계, 성과 미확인)는 처음 보이는 영역에 유지한다. 요약과 상세에서 같은 설명을 길게 반복하지 않는다.
- 브라우저 기본 펼치기 요소인 `<details>`와 첫 자식 `<summary>`를 사용한다. 초기에는 닫힌 상태이며, 외부 스크립트 없이 상태별 문구를 스타일로 구분한다.
- Tab으로 조작부에 이동하고 Enter·Space로 열고 닫을 수 있게 한다. 초점 테두리, 최소 높이 44px의 클릭 영역과 상태를 알 수 있는 문구를 제공한다.
- 좁은 화면에서도 가로 넘침이나 별도의 내부 스크롤 상자가 생기지 않게 한다. 인쇄 시 상세가 누락되지 않도록 인쇄 스타일을 적용하고 실제 인쇄 미리보기 확인 여부를 구분해 보고한다.

## 4. 유지하는 디자인과 분석 내용

### 제목·핵심 문장·출처

- 뉴스레터 제목 h1 → 분야·코너 h2 → 기사·연습 제목 h3 → 분석 영역 h4 → 굵은 세부 질문 순서로 크기와 여백을 구분한다. h1~h4는 HTML의 제목 단계다.
- 숫자는 코너 순번 `01.`~`05.`에 사용하고, 분석 영역은 `■`, 세부 질문은 `•`로 구분한다.
- 뉴스 기사 제목 아래에 옅은 배경·경계선이 있는 핵심 상자를 둔다. `💡 핵심 한 줄`과 요약을 별도 줄에 놓고 요약 문장 전체를 굵게 표시한다.
- 뉴스마다 기업·기관, 발표일, 지역, 출처 유형·원문 링크를 간결하게 표시한다. 연습에는 별도의 연습 목표·참고 출처를 제공한다.
- UTF-8 단일 HTML에 스타일을 포함한다. 한국어 언어 설정·모바일 화면 설정을 제공하고 외부 글꼴·스크립트·이미지에 의존하지 않는다. 360~390px 화면의 줄바꿈, 대비와 키보드 접근성을 유지한다.
- 머리말에는 실행일·수집 기간·실제 구성·뉴스의 지역 및 출처 유형별 건수·연습 참고 출처·부족 사항을 표시한다.
- 기존 자료 재작성에서는 실행 방식·입력 자료 링크·원래 기간·원문 확인일을 표시하되 `인터넷 검색·원문 재확인: 하지 않음` 항목은 최종 화면에서 제외한다. 검색 미실시 기록은 작업일지와 완료 보고에 남긴다.

### 직무 분석 2개에 각각 보존할 4개 영역·질문 8개

다음 답은 더 읽기 안에 모두 유지한다. 확인되지 않은 답도 생략하지 않고 `확인되지 않음`으로 표시한다.

#### ■ 무슨 일이 있었나

- 어떤 기업에서 무슨 일이 있었는가?
- 어떤 업무 문제를 해결하려 했는가?

#### ■ 어떻게 구현했나

- AI가 어떤 시스템·데이터와 연결됐는가?
- 무엇이 자동화됐고 무엇은 사람이 확인하는가?

#### ■ 근거가 있는가

- 실제 성과를 보여주는 근거가 있는가?

#### ■ 나의 직무와 어떻게 연결되는가

- AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?
- 나의 기존 경험과 연결되는 역량은 무엇인가?
- 더 공부하거나 직접 만들어볼 것은 무엇인가?

마지막에 직무 학습 포인트를 한두 문장으로 정리한다. 전체 종합은 분석 2건의 공통 업무 문제·중요 역량·다음 학습을 짧은 글머리표 3개로 요약한다. 각 항목은 1~2문장으로 해당 기사 번호에 연결한다.

## 5. 실행 방식과 출처 검증

스킬은 `$enterprise-ai-newsletter`로 명시적으로 호출할 때 사용한다. 규칙 수정, 자료 조사, 뉴스레터 제작은 서로 다른 작업이다. 실행 방식·입력·검색 여부·기간·구성·분량·정확한 출력 경로를 먼저 안내하고 이미 승인받은 범위는 다시 묻지 않는다.

### 새 자료 수집

- 최근 3개월 뉴스의 국내·해외 검색어를 최대 4개까지 묶어 검색한다. URL 기준으로 중복과 후보 상태를 관리한다.
- 뉴스 최종 4건 + 예비 최대 2건, 최대 6건을 깊게 검증한다. 연습 개념 참고 자료 1건은 별도 선정한다.
- 부족한 코너·분야·지역과 연습 참고 자료의 보충 검색은 한 번 수행한다. 예비만 부족할 때 추가 검색은 필수가 아니다. 이후에도 부족하면 실제 건수와 이유를 보고한다.
- 원문에서 제목·날짜·작성 주체·내용·수치를 직접 확인한다. 누락·열기 실패 외에는 같은 URL을 불필요하게 다시 열지 않는다. 날짜·핵심 수치가 모호하거나 충돌할 때만 보조 출처를 확인한다.
- 실제 수집 시작·검증 완료 시각과 소요 시간을 기록하고 검증 자료 묶음(.md)을 먼저 저장한다.

### 자료 조사·출처 검증만 요청한 경우

- 뉴스의 사실·출처·날짜·근거 수준·미확인 사항과 연습용 참고 개념·출처·목표·소재 메모까지만 하나의 검증 묶음으로 저장한다.
- **뉴스레터 본문·완성된 연습 문제·예시 답안·HTML은 만들지 않는다.** 사용자의 별도 제작 요청을 기다린다. 자료를 확인했다는 말이나 선호 방향 동의를 제작 요청으로 간주하지 않는다.
- 검증 묶음의 사실·한계는 충분히 보존한다. 본문 축약은 최종 HTML의 작성 규칙이며 검증 기록을 생략하는 기준이 아니다.
- 새 수집과 뉴스레터 제작을 함께 요청받은 경우에는 검증 묶음 저장 후 같은 실행 버전의 HTML을 작성한다.

### 기존 검증 자료 재작성

- 승인한 검증 묶음만 사실의 기준으로 사용하고 인터넷 검색·원문 재확인을 하지 않는다.
- 직무 2건과 두 재미 유형의 읽을거리 각 1건을 고르고 별도 연습 참고 자료를 사용한다. 적합한 재미 소재나 연습 참고가 없으면 부족함을 밝히고, 새 수집이 이미 허용되지 않았다면 전환 여부를 확인한다.
- 기술 해설을 실제 엉뚱한 실험이나 웃긴 경험으로 꾸미지 않는다. 검증 자료에 없는 사실·성과·효과 주장을 추가하지 않는다.
- 입력 묶음과 이전 결과는 보존하고 HTML만 새 파일로 저장한다. 원래 기간·확인일을 유지하며 현재 다시 검증한 최신 뉴스처럼 표현하지 않는다.
- 재작성 시간과 로컬 검증 결과를 기록한다. 원문 링크의 현재 접속 상태는 재확인하지 않는다.

### 공통 신뢰 기준

정부·공공기관·국제기구, 대학·연구기관, 기업 공식 홈페이지·기술 문서·보도자료·공식 영상, 작성자·발표일·원문이 확인되는 신뢰도 높은 언론 자료를 우선한다. 출처 유형은 공공·연구 자료 / 기업 공식 발표 / 기업 공식 기술 콘텐츠 / 독립 언론 보도로 구분한다.

채용·중복·출처 불명·원문 미확인·제품 광고만 있는 자료는 제외한다. 읽을거리에도 같은 날짜·원문 검증 기준을 적용한다. 연습의 개념 참고 자료는 3절의 기간 예외를 따른다.

기업 성과는 기업 공식 발표 기준으로 표시하며 원문에 없는 개발자 역할은 `직무 관점의 해석`으로 구분한다. 미확인 내용을 추측하지 않고 긴 원문을 복제하지 않는다.

## 6. 저장과 문서 간 연결

- 현재 기획 기준: 이 PRD v05.

- [이전 PRD v04](../../v04/docs/기획서-기업용-ai-뉴스수집-2026-09-15-v04.md)는 당시 버전의 기록으로 보존한다.
- [스킬 실행 규칙](../../../../../.agents/skills/enterprise-ai-newsletter/SKILL.md), [뉴스레터 형식](../../../../../.agents/skills/enterprise-ai-newsletter/references/newsletter-format.md), [자료 선정 규칙](../../../../../.agents/skills/enterprise-ai-newsletter/references/source-selection-rules.md), [검증 묶음 형식](../../../../../.agents/skills/enterprise-ai-newsletter/references/research-pack-format.md)을 실행 기준으로 함께 대조한다.
- 앞으로 요구사항이 바뀌면 PRD와 관련 스킬 규칙의 반영 범위를 함께 확인한다. 사용자 요청이 우선이며, 과거 PRD의 다른 기준을 현재 기준으로 혼용하지 않는다.
- 새 PRD는 기존 `PRD/v번호/docs/` 구조를 유지한다. 기존 파일은 이동·수정하지 않는다.
- 뉴스레터 실행 버전은 PRD 버전과 독립적으로 관리한다. 다음 빈 `newsletters/vNN/`에 요청받은 출력만 저장한다. PRD v05를 만들었다고 뉴스레터 v05도 생성됐다는 뜻은 아니다.

```text
projects/enterprise-ai-newsletter-2026-09-15-v01/
├─ PRD/v05/docs/기획서-기업용-ai-뉴스수집-2026-09-16-v05.md
├─ docs/00-latest.md
└─ newsletters/vNN/                 # 후속 실행 때 다음 빈 번호 사용
   ├─ research-pack-YYYY-MM-DD-vNN.md  # 새 수집 결과만
   └─ newsletter-YYYY-MM-DD-vNN.html   # 제작 요청을 받은 경우만
```

이번에는 PRD v05와 최신 연결만 갱신하고, 앞서 수정한 스킬과 대조한다. 새 자료 조사·검증 묶음·HTML은 생성하지 않는다. Git 커밋·푸시, 외부 전송·배포·예약 실행은 별도 요청 범위다.

## 7. 후속 뉴스레터의 완료 조건

아래는 앞으로 제작한 결과물을 확인할 기준이며 이번 기획서 수정으로 충족됐다는 뜻이 아니다.

- 뉴스 목표 4건과 연습 1개가 구분되고 두 재미 유형이 각각 포함된다. 부족하면 실제 구성·이유를 밝힌다.
- 뉴스별 핵심 한 줄과 출처·날짜가 검증 묶음과 일치하며 기업 주장·해석·미확인 사항이 구분된다.
- 직무 본문은 짧게 보이고 각 상세 안에 4개 영역·질문 8개의 답이 있다. 출처와 주요 한계는 접힌 영역 밖에서도 보인다.
- 더 읽기를 누르면 해당 글 아래에서 열리고 다시 접힌다. 연습 예시는 별도로 접혀 있다. 마우스와 키보드 동작을 각각 확인한다.
- 제목 단계·핵심 상자·분량·한글·내부 링크와 360~390px 화면의 가독성을 확인한다. 인쇄 미리보기에서 상세 내용 누락 여부를 별도로 확인한다.
- 재작성은 입력 링크·원래 기간·확인일을 유지하고 검증 자료 밖의 새 사실을 추가하지 않는다.
- 파일 검사, 화면 확인, 동작 확인과 사용자 직접 확인을 구분해 보고한다. 실행하지 못한 검증은 완료로 적지 않는다.
- 과거 결과물을 보존한다. 자료 조사만 요청받았다면 검증 묶음 저장에서 종료하고 HTML 미제작을 명시한다.
