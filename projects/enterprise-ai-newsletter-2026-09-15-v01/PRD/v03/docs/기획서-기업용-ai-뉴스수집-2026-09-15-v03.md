## 1. 풀고자 하는 문제

- **지금은 이렇게 해요 (현재 방식):**
  기업용 AI·업무자동화 산업과 관련 직무의 최신 정보를 알고 싶을 때마다 직접 검색하고 여러 자료를 따로 읽는다.

- **이게 불편해요 (문제점):**
  어떤 자료가 믿을 만한지 판단하기 어렵고, 중복되거나 광고성인 자료가 섞인다. 산업과 직무에 어떤 의미가 있는지 스스로 다시 정리해야 한다. 분석 질문을 모두 큰 제목으로 나열하면 내용이 보고서처럼 딱딱해지고 읽는 흐름도 자주 끊긴다.

- **이렇게 되면 좋겠어요 (이상):**
  실행일 기준 최근 3개월의 신뢰할 수 있는 자료만 찾아 출처와 함께 분류·요약하고, 관심 직무의 실제 역할과 필요한 역량까지 자연스러운 흐름으로 이해하도록 돕는 한국어 뉴스레터가 만들어지면 좋겠다. 이미 검증한 자료가 있으면 인터넷을 다시 검색하지 않고 글의 구성과 문체만 빠르게 개선할 수 있어야 한다.

### 이 기획서에서 말하는 직무 이해

> 기업의 업무 과정을 분석하고, 기존 시스템·데이터와 AI를 연결하여, 사람이 안전하게 확인할 수 있는 자동화 시스템을 만들고 운영하는 직무로 이해한다.

직무 이해는 단순히 `하는 일`이나 `취업 준비 항목` 하나만 뜻하지 않는다. 다음 세 가지를 함께 이해하는 것을 목표로 한다.

1. 이 직무는 어떤 업무 문제를 해결하는가?
2. 실제 현장에서는 어떤 방식과 과정으로 해결하는가?
3. 그 일을 잘하기 위해 어떤 기술·업무·소통 역량이 필요한가?

## 4. 핵심 기능 (MVP) : 이것만 되면 일단 성공

1. 요청 목적에 따라 `새 자료 수집`과 `기존 검증 자료 재작성` 중 한 방식을 선택하고, 실행 전에 입력·검색 여부·출력 경로를 사용자에게 보여준다.
2. 새 자료 수집에서는 최근 3개월의 신뢰 가능한 자료를 검색해 최종 7건과 예비 2건까지만 검증하고, 검증 자료 묶음과 뉴스레터를 함께 저장한다.
3. 기존 검증 자료 재작성에서는 인터넷 검색 없이 검증 자료 묶음만 사용해 문체, 제목, 문단 길이, 정보 배치와 설명 난이도를 바꾼 새 뉴스레터를 만든다.
4. 자료를 산업 동향, 기술·제품 동향, 기업의 AI·업무자동화 적용 사례, 기업의 기술개발 사례, 기업 공식 블로그·기술 문서·유튜브 콘텐츠로 분류한다.
5. 기사별 분석 질문 8개를 빠짐없이 다루되, 독자가 읽기 편하도록 4개의 큰 영역으로 묶어 한국어 뉴스레터로 작성한다.

- **AI에게 맡길 것:** 실행 방식에 맞는 검색어 구성, 자료 검색과 검증, 날짜·출처 확인, 중복 제거, 관련성 판단, 분류, 한국어 요약, 읽기 쉬운 글 구성과 직무 관점의 의미 설명
- **사람이 확인할 것:** 실행 방식, 입력 자료, 관심 조건 변경, 최종 자료와 요약, 가독성, 스킬 제작·수정 명령과 뉴스레터 실행 명령

### 두 가지 실행 방식

#### 1. 새 자료 수집

- 최근 3개월 자료를 새로 검색하고 원문을 확인한다.
- 국내·해외 검색어를 묶고 신뢰도가 높은 공식 출처부터 살펴본다.
- 후보는 최종 7건과 예비 2건, 최대 9건에서 중단한다.
- 공식 원문에서 날짜나 핵심 성과 수치가 불명확하거나 다른 자료와 충돌할 때만 보조 출처로 교차 확인한다.
- 검증 자료 묶음과 뉴스레터를 같은 버전 폴더에 각각 새 파일로 저장한다.

#### 2. 기존 검증 자료 재작성

- 저장된 검증 자료 묶음만 사용하고 인터넷 검색과 원문 재확인을 하지 않는다.
- 기존 뉴스레터의 문장을 기계적으로 고치는 대신 검증 자료에서 글을 새로 구성한다.
- 문체, 제목, 문단 길이, 정보 배치와 설명 난이도만 바꾼다.
- 검증 자료에 없는 새로운 사실이나 수치를 추가하지 않는다.
- 필요한 정보가 없으면 `확인되지 않음`으로 표시하거나 새 자료 수집으로 전환할지 사용자에게 확인한다.
- 검증 자료 묶음은 새로 만들지 않고 뉴스레터만 다음 버전의 새 파일로 저장한다.

### 직무 이해의 다섯 영역

1. **업무 문제 이해:** 기업이 어떤 반복 작업이나 운영 문제를 해결하려 했고 왜 AI·자동화가 필요했는지 파악한다.
2. **실제 개발 과정:** 기존 시스템, 데이터베이스, API와 AI가 어떻게 연결되고 에이전트가 어디까지 판단·실행하는지 파악한다.
3. **운영과 안전:** 오류, 예외 상황, 보안, 사람의 검토와 승인, 배포 후 성능·비용 관리를 파악한다.
4. **기업 사례와 성과:** 실제 업무 적용 여부와 시간·비용·품질 변화 등 확인 가능한 성과를 파악한다.
5. **필요한 역량:** 시스템 분석, 데이터베이스·API 연결, 개발·운영, AI 활용, 현업 소통과 요구사항 정리 역량을 파악한다.

### 신뢰할 수 있는 출처 기준

- 정부·공공기관 및 국제기구의 공식 발표·보고서
- 대학·연구기관 및 학술단체의 공식 자료
- 기업 공식 홈페이지, 기술 블로그, 개발자 문서, 보도자료와 공식 유튜브 채널
- 작성 주체, 발표일과 원문을 확인할 수 있는 신뢰도 높은 언론 기사
- 공식 원문에서 날짜나 중요한 성과 수치가 불명확하거나 자료끼리 충돌할 때 보조 출처로 교차 확인한다.
- 기업이 직접 공개한 자료는 객관적인 기사와 구별해 `기업 공식 발표` 또는 `기업 공식 기술 콘텐츠`로 표시한다.

## 5. 결과와 완료 조건

### 결과물과 저장 위치

실행할 때 다음의 비어 있는 버전 폴더에 새 파일로 저장한다. 실제 입력·출력 경로와 파일 목록은 실행 전에 사용자에게 보여주고 확인받는다.

```text
projects/enterprise-ai-newsletter-2026-09-15-v01/newsletters/vNN/
├─ research-pack-YYYY-MM-DD-vNN.md   # 새 자료 수집일 때만 생성
└─ newsletter-YYYY-MM-DD-vNN.md
```

- **새 자료 수집:** 검증 자료 묶음과 뉴스레터를 함께 생성한다.
- **기존 검증 자료 재작성:** 뉴스레터만 생성하고 사용한 검증 자료 묶음 경로를 표시한다.
- **공통 보존 원칙:** 같은 이름의 파일이나 기존 버전을 덮어쓰지 않는다.

### 기사 한 건의 읽기 구조

1. 기사 제목
2. `핵심 한 줄`
3. 기업·기관, 발표일, 지역, 자료 유형, 출처와 원문 링크를 담은 간결한 기본 정보
4. 아래 4개의 큰 분석 영역
5. 독자가 기억하거나 직접 실습할 내용을 정리한 직무 학습 포인트

### 기사별 4개 큰 분석 영역과 필수 질문 8개

#### 1. 무슨 일이 있었나

- **어떤 기업에서 무슨 일이 있었는가?**
  기업·기관명, 발표 주체, 적용 또는 발표된 내용을 요약한다.
- **어떤 업무 문제를 해결하려 했는가?**
  기존 업무 방식의 불편, 반복 작업, 운영 문제와 AI·자동화가 필요했던 이유를 설명한다.

#### 2. 어떻게 구현했나

- **AI가 어떤 시스템·데이터와 연결됐는가?**
  기사에서 확인 가능한 기존 시스템, 데이터베이스, API, 업무 도구와 AI의 연결 관계를 설명한다.
- **무엇이 자동화됐고 무엇은 사람이 확인하는가?**
  AI가 분석·판단·실행하는 범위와 사람이 검토·승인·예외 처리하는 범위를 구분한다.

#### 3. 근거가 있는가

- **실제 성과를 보여주는 근거가 있는가?**
  시간, 비용, 품질, 처리량 등의 수치와 실제 운영 여부를 확인한다. 근거가 없으면 없다고 명시한다.

#### 4. 나의 직무와 어떻게 연결되는가

- **AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?**
  업무 분석, 시스템 설계, 데이터·API 연결, 개발, 테스트, 배포, 운영과 협업 중 어떤 역할이 필요한 사례인지 설명한다.
- **나의 기존 경험과 연결되는 역량은 무엇인가?**
  Java 운영개발, 시스템 분석, 장애 대응, 데이터베이스·API 연결, 운영 부서 협업 경험과 연결되는 지점을 설명한다.
- **더 공부하거나 직접 만들어볼 것은 무엇인가?**
  사례를 이해하기 위해 더 공부할 개념과 포트폴리오로 시험해볼 수 있는 작은 실습 아이디어를 제안한다.

### 가독성 작성 원칙

- 각 자료의 시작에 가장 중요한 내용을 설명하는 `핵심 한 줄`을 둔다.
- 진로를 준비하는 비개발자도 이해할 수 있는 친근한 설명체로 작성한다.
- 전문성은 유지하되 보고서처럼 딱딱한 표현과 불필요하게 긴 문장을 피한다.
- 전문용어는 처음 등장할 때 바로 쉬운 말로 풀이한다.
- 한 문단은 2~4문장을 기본으로 하고, 분석 질문 하나에는 원칙적으로 1~2개의 짧은 문단이나 글머리표로 답한다.
- 같은 기업 정보나 성과 수치를 여러 영역에서 반복하지 않는다.
- 기술 설명만 나열하지 않고 `기업이 해결하려던 업무 문제 → 구현 방식 → 결과 → 직무 의미`의 흐름으로 연결한다.
- 해외 자료도 자연스러운 한국어로 설명하되 제품명, 기술명과 고유명사의 의미를 바꾸지 않는다.
- 모든 자료에 출처명과 원문 링크를 표시한다.

### 사실과 해석을 구분하는 원칙

- **확인된 사실:** 원문에서 직접 확인할 수 있는 내용과 수치는 자연스럽게 서술한다.
- **직무 관점의 해석:** 개발자 역할이나 활용 가능성이 원문에 직접 나오지 않았다면 해석임을 표시한다.
- **확인되지 않음:** 원문이나 검증 자료에 정보가 없으면 해당 부분에서만 표시하고 추측으로 채우지 않는다.
- **기업의 성과 주장:** 기업이 직접 공개한 성과 수치는 `기업 공식 발표 기준`이라고 표시한다.
- 사실·해석 표시를 모든 문장에 반복해 읽는 흐름을 끊지 않는다.

### 실행 전 확인 항목

- 사용할 실행 방식
- 입력할 검증 자료 또는 새 검색 기간
- 인터넷 검색 여부
- 목표 수량과 국내·해외 구성
- 적용할 문체, 기사별 예상 분량과 4개 큰 분석 영역
- 새로 생성할 파일의 정확한 경로

### 완료 조건

- 뉴스레터에 기준을 만족하는 자료가 최대 7건 포함된다.
- 각 자료에 핵심 한 줄과 간결한 기본 정보가 있다.
- 각 자료가 4개의 큰 영역으로 구성되고 기존 분석 질문 8개의 답이 빠짐없이 포함된다.
- 확인된 사실, 직무 관점의 해석과 확인되지 않은 내용이 구분된다.
- 검증 자료에 없는 새로운 사실이나 수치가 추가되지 않는다.
- 전문용어가 설명 없이 사용되지 않고 같은 정보가 불필요하게 반복되지 않는다.
- 모든 자료에서 출처와 원문 링크를 확인할 수 있다.
- 기존 뉴스레터와 검증 자료가 보존된다.

### 자료가 부족하거나 확인하기 어려운 경우

- 기준 미달 자료로 7건을 채우지 않고 `조건에 맞는 자료가 부족합니다`라는 안내와 실제 수집 건수·비율을 표시한다.
- 링크 오류, 날짜 불명, 원문 확인 불가 또는 서로 충돌하는 정보는 본문에서 제외하거나 `사람 확인 필요`로 표시한다.
- 재작성에 필요한 사실이 검증 자료에 없으면 임의로 검색하지 않고 새 자료 수집 전환 여부를 확인한다.

### 최종 학습 완료 상태

뉴스레터를 읽은 뒤 다음을 자신의 말로 설명할 수 있으면 직무 이해에 도움이 된 결과로 본다.

- 기업이 어떤 업무 문제를 해결했는가?
- AI와 기존 시스템·데이터는 어떻게 연결됐는가?
- 무엇이 자동화됐고 사람은 무엇을 확인했는가?
- 자동화 과정에서 개발자는 어떤 역할을 했는가?
- 어떤 기술·업무·소통 역량이 필요했는가?
- 나의 경험과 앞으로의 학습 방향은 어떻게 연결되는가?
