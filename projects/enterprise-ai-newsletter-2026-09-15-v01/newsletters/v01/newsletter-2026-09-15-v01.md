## 1. 금융위원회, 금융권 AI 7대 원칙과 사람의 최종 책임을 제시

- 지역: 국내
- 분류: 산업 동향·정책
- 출처 유형: 공공기관 공식 발표
- 발표일: 2026-06-18
- 출처: 금융위원회
- 원문: [정부와 금융권이 함께 금융권 AX를 가속화해 나가겠습니다](https://www.fsc.go.kr/po010101/87142)

### 1. 어떤 기업에서 무슨 일이 있었는가?

- **확인된 사실:** 금융위원회가 금융회사·유관기관과 금융권 인공지능 전환(AX) 간담회를 열고, 모든 금융회사가 자율규제로 적용할 `금융분야 인공지능 가이드라인` 개정안을 발표했습니다. 가이드라인은 2026-06-22 시행 예정으로 안내됐습니다.
- **확인된 사실:** 거버넌스, 합법성, 보조수단성, 신뢰성, 금융안정성, 신의성실, 보안성의 7대 원칙이 제시됐습니다.

### 2. 어떤 업무 문제를 해결하려 했는가?

- **확인된 사실:** 금융회사가 AI를 고객 서비스와 내부 의사결정 보조에 확대할 때 생기는 책임소재, 데이터 통제, 보안, 사이버 위험과 소비자 보호 문제를 다룹니다.
- **자료를 바탕으로 한 해석:** 기술 도입 여부보다 먼저 “어떤 위험이면 누가 멈추고 최종 결정할 것인가”를 정해야 한다는 요구입니다.

### 3. AI가 어떤 시스템·데이터와 연결됐는가?

- **확인된 사실:** 자료는 고객정보 분석, 리스크·데이터 분석, 상품 추천·가입·결제 같은 금융 업무를 언급합니다.
- **아직 알 수 없는 내용:** 특정 금융회사의 데이터베이스, API, 모델 또는 실제 연결 구조는 이 정책 발표만으로 확인할 수 없습니다.

### 4. 무엇이 자동화됐고 무엇은 사람이 확인하는가?

- **확인된 사실:** AI는 현 단계에서 업무의 보조수단이며, 최종 의사결정과 책임은 임직원이 맡아야 한다고 명시했습니다. 고위험 AI에는 별도 법적 의무도 확인해야 합니다.
- **자료를 바탕으로 한 해석:** 실제 시스템에는 사람 승인 단계, 위험도에 따른 자동 실행 제한, 중지 기능과 책임 기록이 필요합니다.

### 5. 실제 성과를 보여주는 근거가 있는가?

- **확인된 사실:** 개정 가이드라인, 위험관리 프레임워크와 보안 안내서의 시행·배포 일정은 확인됩니다.
- **아직 알 수 없는 내용:** 처리 시간 단축이나 오류율 감소 같은 현장 성과 수치는 제시되지 않았습니다. 따라서 이 자료는 성과 사례가 아니라 제도·설계 기준으로 봐야 합니다.

### 6. AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?

- **자료를 바탕으로 한 해석:** 정책 원칙을 실제 기능으로 바꾸는 일을 합니다. 예를 들면 사용자 권한, 사람 승인, 입력·출력 기록, 데이터 품질 점검, 이상 상황 알림, 모델 변경 관리와 감사 기록을 설계합니다.
- **아직 알 수 없는 내용:** 특정 개발 조직의 역할 분담과 기술 도구는 공개되지 않았습니다.

### 7. 나의 기존 경험과 연결되는 역량은 무엇인가?

- Java 운영·개발에서 해온 권한 확인, 장애 기록, 변경 이력, 운영자 승인과 원인 분석 경험이 그대로 연결됩니다.
- 특히 “자동화가 실패했을 때 누가 무엇을 보고 복구하는가”를 정하는 운영 관점은 금융 AI의 책임성과 신뢰성을 구현하는 핵심 역량이 됩니다.

### 8. 더 공부하거나 직접 만들어볼 것은 무엇인가?

- 공부: 금융 AI 7대 원칙, 역할 기반 접근제어(RBAC: 사람의 역할에 따라 기능과 데이터를 제한하는 방식), 감사 로그, 사람 승인 구조.
- 실습: 고객 문의를 AI가 분류하되 고위험 요청은 자동 처리하지 않고 담당자 승인함으로 보내며, 판단 근거와 처리 이력을 남기는 작은 Java API를 만들어볼 수 있습니다.

## 2. 삼성SDS 조사, 높은 GenAI 활용 뒤의 Shadow AI 위험

- 지역: 국내
- 분류: 산업 동향·기업 조사
- 출처 유형: 기업 공식 기술 콘텐츠
- 발표일: 2026-07-22
- 출처: 삼성SDS
- 원문: [국내 기업 GenAI 활용 실태 - 업무 효율 향상 이면의 Shadow AI 리스크](https://www.samsungsds.com/kr/insights/enterprise-genai-usage-survey_part1.html)

### 1. 어떤 기업에서 무슨 일이 있었는가?

- **확인된 사실:** 삼성SDS가 국내 기업·공공기관 임직원 1,750명을 대상으로 한 생성형 AI 활용 조사 결과를 공개했습니다.
- **확인된 사실:** 조사 자료는 하루 평균 활용 시간 3.25시간, 4시간 이상 사용 43%, 워크플로 자동화 시스템·앱 개발 및 활용 13%, 비공식 AI 사용인 Shadow AI 경험 38%를 제시합니다.

### 2. 어떤 업무 문제를 해결하려 했는가?

- **확인된 사실:** 개인 단위의 AI 활용이 늘었지만 승인받지 않은 서비스 사용, 민감정보 노출, 결과 품질 편차, 기업 데이터 및 실제 업무 절차와의 연결 부족이 남아 있음을 지적합니다.
- **자료를 바탕으로 한 해석:** “직원이 AI를 많이 쓴다”와 “회사가 안전하게 업무를 자동화했다”는 서로 다른 성숙 단계입니다.

### 3. AI가 어떤 시스템·데이터와 연결됐는가?

- **확인된 사실:** 자료는 기업 데이터 연결, 업무 흐름 자동화, 보안·거버넌스를 통합한 기업용 AI 운영 기반이 필요하다고 설명합니다.
- **아직 알 수 없는 내용:** 조사 응답 기업들이 실제로 어떤 ERP, 문서 저장소, 데이터베이스 또는 API를 연결했는지는 공개되지 않았습니다.

### 4. 무엇이 자동화됐고 무엇은 사람이 확인하는가?

- **확인된 사실:** 응답자 중 일부가 워크플로 자동화 시스템·앱을 개발하거나 사용한다는 비율은 제시됐지만, 구체적인 업무 단계와 사람의 승인 범위는 제시되지 않았습니다.
- **자료를 바탕으로 한 해석:** 조직 차원의 자동화라면 승인된 AI 도구, 입력 가능 데이터, 결과 검토자와 예외 처리 절차를 함께 정해야 합니다.

### 5. 실제 성과를 보여주는 근거가 있는가?

- **확인된 사실:** 표본 수와 활용 시간·용도·Shadow AI 비율이라는 조사 근거가 있습니다.
- **아직 알 수 없는 내용:** 조사 설계의 세부 표본 구성과 응답자의 자기보고 편향, 기업별 생산성 변화는 본문만으로 충분히 검증하기 어렵습니다. 기업 공식 조사 자료라는 점도 함께 고려해야 합니다.

### 6. AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?

- **자료를 바탕으로 한 해석:** 승인된 AI 접점을 만들고, 사내 데이터와 업무 시스템을 API로 연결하며, 민감정보 차단·사용 기록·결과 평가를 운영합니다. 단순 챗봇 개발보다 조직 전체가 안전하게 쓰는 공통 기반을 만드는 역할에 가깝습니다.

### 7. 나의 기존 경험과 연결되는 역량은 무엇인가?

- 운영 시스템에서 사용 권한과 로그를 관리하고 DB·API를 연결한 경험은 Shadow AI를 줄이는 안전한 사내 AI 환경 구축에 직접 연결됩니다.
- 현업 요청을 듣고 기존 절차를 분석한 경험은 “자유로운 질문”을 “통제 가능한 업무 흐름”으로 바꾸는 데 유용합니다.

### 8. 더 공부하거나 직접 만들어볼 것은 무엇인가?

- 공부: 데이터 등급 분류, 개인정보 마스킹, 프롬프트와 응답 로그 정책, 사내 AI 사용 규칙.
- 실습: 승인된 문서만 검색하고 민감정보가 입력되면 전송을 중단하며 모든 요청을 감사 로그에 남기는 사내 지식검색 시제품을 만들어볼 수 있습니다.

## 3. LG CNS, 실제 ERP 운영 데이터로 테스트 전 과정을 자동화

- 지역: 국내
- 분류: 기업의 기술개발 사례
- 출처 유형: 기업 공식 발표
- 발표일: 2026-06-25
- 출처: LG CNS
- 원문: [LG CNS, 에이전틱 AI 탑재한 ERP 테스트 솔루션 출시](https://www.lgcns.com/kr/newsroom/press/detail.ax-2606-6)
- 날짜 교차 확인: [뉴스투데이 보도](https://www.news2day.co.kr/article/20260625500166)

### 1. 어떤 기업에서 무슨 일이 있었는가?

- **확인된 사실:** LG CNS가 SAP ERP와 S/4HANA 전환·구축 과정의 테스트를 지원하는 `PerfecTwin ERP Edition`을 출시했습니다.
- **확인된 사실:** 회사 발표에 따르면 에이전틱 AI가 테스트 시나리오 생성, 실행, 오류 원인 분석, 후속 조치 제안과 보고서 작성까지 지원합니다.

### 2. 어떤 업무 문제를 해결하려 했는가?

- **확인된 사실:** ERP 전환 때 업무 담당자가 검증 항목과 시나리오를 직접 설계해야 하고, 많은 업무 절차를 반복 시험해야 하는 시간·누락 문제를 줄이려 했습니다.
- **자료를 바탕으로 한 해석:** 시스템 전환의 병목은 코딩만이 아니라 “실제 업무가 이전과 똑같이 동작하는지 증명하는 일”에 있다는 사례입니다.

### 3. AI가 어떤 시스템·데이터와 연결됐는가?

- **확인된 사실:** SAP ERP·S/4HANA, 실제 거래 데이터, 기업의 업무 프로세스와 운영 데이터를 분석해 테스트 시나리오를 만듭니다.
- **아직 알 수 없는 내용:** 고객 데이터의 반출 방지·비식별 처리 방식, 구체적인 API와 모델, 운영 환경별 연결 방식은 공개 자료만으로 확인되지 않습니다.

### 4. 무엇이 자동화됐고 무엇은 사람이 확인하는가?

- **확인된 사실:** 테스트 준비, 시나리오 생성, 실행, 이상 징후와 오류 원인 분석, 조치안 제안, 결과 보고서 작성이 자동화 범위에 포함됩니다.
- **확인된 사실:** 오류 수정과 재검증까지 여러 에이전트가 자율 수행하는 기능은 향후 고도화 계획으로 소개됐습니다. 현재 완료된 기능으로 보면 안 됩니다.
- **아직 알 수 없는 내용:** 조치안 승인과 실제 운영 반영을 누가 최종 결정하는지는 명시되지 않았습니다.

### 5. 실제 성과를 보여주는 근거가 있는가?

- **확인된 사실:** 회사는 테스트 시나리오 설계에 수일 걸리던 일을 수 시간 수준으로 단축할 수 있다고 밝혔습니다.

### 2. 어떤 업무 문제를 해결하려 했는가?

- **확인된 사실:** 미국 주마다 결제·입금 한도·출금·책임 있는 게임 규정이 다르고, 대형 경기 중에는 2분마다 40건이 넘는 문의가 몰리는 문제를 다뤘습니다.
- **확인된 사실:** 단순 의사결정 나무형 챗봇은 복잡한 문맥과 위험 신호를 다루기 어렵고 사람 상담 대기열과 비용이 함께 늘었습니다.

### 3. AI가 어떤 시스템·데이터와 연결됐는가?

- **확인된 사실:** 모바일 앱→Salesforce Einstein→REST 호출→Amazon EKS의 Spring AI 서비스→Amazon Bedrock Guardrails→책임 있는 게임 분류기→총괄 에이전트로 이어집니다.
- **확인된 사실:** 총괄 에이전트는 RAG(관련 문서를 찾아 답변 근거로 주는 방식), 계정·거래내역 MCP 서버와 사람 이관 도구를 사용합니다. 문서는 MongoDB Atlas에 벡터 형태로 저장됩니다.

### 4. 무엇이 자동화됐고 무엇은 사람이 확인하는가?

- **확인된 사실:** 고객이 직접 사람을 요청하거나 사람의 판단이 필요한 상황도 이관 대상입니다. 낮은 위험 신호는 기록해 준법 검토에 사용합니다.

### 5. 실제 성과를 보여주는 근거가 있는가?

- **확인된 사실:** AWS 공식 기술 글은 실제 요청량, 시스템 구조, 서비스 선택 이유와 확장 방법을 상세히 공개합니다.

### 6. AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?

### 7. 나의 기존 경험과 연결되는 역량은 무엇인가?

- 상담 시스템과 내부 계정·거래 시스템 사이의 연결을 추적하는 일은 기존 시스템 분석과 운영 협업 역량이 강점이 되는 영역입니다.

### 8. 더 공부하거나 직접 만들어볼 것은 무엇인가?

## 7. UiPath·PLDT, Outlook·SharePoint를 연결한 지식·위험관리 에이전트 운영

- 지역: 해외(필리핀)
- 분류: 기업의 AI·업무자동화 적용 사례
- 출처 유형: 기업 공식 발표·고객 사례
- 발표일: 2026-09-11
- 출처: UiPath
- 원문: [UiPath Powers PLDT's AI Transformation](https://www.uipath.com/newsroom/uipath-powers-pldt-ai-transformation-amid-surging-demand-for-digital-connectivity)
- 상세 사례: [PLDT turns manual effort into intelligent action with agentic AI built on UiPath](https://www.uipath.com/resources/automation-case-studies/pldt-transforms-operations-with-agentic-ai-built-on-uipath)

### 1. 어떤 기업에서 무슨 일이 있었는가?

- **확인된 사실:** 필리핀 통신사 PLDT와 자회사 Smart가 UiPath로 KAI(기업 지식 검색), Ellie(고객 대응과 제안 준비), ERICA(기업 위험 분석) 에이전트를 구축·운영한 사례가 공개됐습니다.
- **확인된 사실:** PLDT의 Intelligent Automation 팀과 UiPath가 KAI를 함께 개선하고 사이버보안 보호 장치를 추가했습니다.

### 2. 어떤 업무 문제를 해결하려 했는가?

- **확인된 사실:** 직원들이 이메일·기술 문서·여러 저장소를 뒤져 고객 질문과 내부 요청에 답하는 데 오래 걸렸고, 제안서 준비와 위험 평가에도 반복적인 정보 수집·정리가 많았습니다.
- **자료를 바탕으로 한 해석:** 정보가 없어서가 아니라 여러 저장소와 업무 단계에 흩어져 있어 사람이 연결하던 문제를 해결한 사례입니다.

### 3. AI가 어떤 시스템·데이터와 연결됐는가?

- **확인된 사실:** UiPath Studio의 Agent Builder로 만든 에이전트가 UiPath Robots를 실행 도구로 사용하고, UiPath Integration Services를 통해 Microsoft Outlook과 SharePoint에 연결됩니다.
- **확인된 사실:** KAI는 승인된 출처의 제품 사양, 시설 가용성, 서비스 준비 문서와 네트워크 성능 데이터를 검색합니다. Ellie는 제품·내부 지식·운영 절차·고객 요구를 사용합니다.

### 4. 무엇이 자동화됐고 무엇은 사람이 확인하는가?

- **확인된 사실:** KAI는 승인된 지식에서 답을 찾고, Ellie는 고객용 문서·비교·제안 초안을 만들며, ERICA는 조직 자료를 위험 문장으로 정리하고 위험도를 매겨 대응안을 제안합니다.
- **확인된 사실:** 자료는 직원들이 반복 정보 수집 대신 고객 관계, 자문과 전략적 위험 대응 같은 판단 업무에 집중한다고 설명합니다.
- **아직 알 수 없는 내용:** 각 결과의 최종 승인자, 자동 전송·시스템 반영 범위와 오류 시 되돌리기 절차는 구체적으로 공개되지 않았습니다.

### 5. 실제 성과를 보여주는 근거가 있는가?

- **확인된 사실:** UiPath·PLDT 공식 사례에 따르면 KAI는 월 11,300건 중 11,000건을 처리하고, 1~5일 걸리던 정보 요청을 1~3초로 단축했으며 연간 약 25,000~30,000시간의 수작업을 줄였습니다.
- **확인된 사실:** ERICA는 2~10일 걸리던 일부 위험 평가 업무를 5분~1일로 줄여 노력 97~99% 감소를 보고했습니다. Ellie는 연간 약 18,000~25,000시간 절감을 제시합니다.
- **주의:** 모두 공급사와 고객사가 공개한 사례 수치이며, 측정 방식과 독립 검증 자료는 확인되지 않았습니다.

### 6. AI 솔루션·업무자동화 개발자는 어떤 일을 했는가?

- **자료를 바탕으로 한 해석:** 각 부서의 반복 업무를 찾고, 승인된 지식 범위를 정하고, Outlook·SharePoint와 기존 자동화 로봇을 연결하며, 응답 정확도를 반복 평가하고 보안 통제를 추가했습니다.
- 한 번에 범용 AI를 만든 것이 아니라 지식검색·영업지원·위험관리처럼 목적이 분명한 에이전트를 각각 설계했습니다.

### 7. 나의 기존 경험과 연결되는 역량은 무엇인가?

- 여러 시스템과 문서 저장소를 연결하고 운영 중 데이터 흐름을 추적한 경험이 핵심입니다. 현업별로 다른 요구를 작은 자동화 단위로 나누는 시스템 분석 경험도 직접 연결됩니다.
- 장애 대응 경험은 잘못된 답변, 연결 실패, 권한 오류를 관찰하고 안전하게 사람 업무로 되돌리는 운영 설계에 도움이 됩니다.

### 8. 더 공부하거나 직접 만들어볼 것은 무엇인가?

- 공부: 기업 지식검색 평가, 출처 제한, 문서 권한 상속, 업무 오케스트레이션(여러 자동화 단계를 순서대로 조정하는 것), 사람 승인 화면.
- 실습: Outlook 대신 샘플 문의함, SharePoint 대신 승인된 문서 폴더를 사용해 답변 초안을 만들고 출처를 표시한 뒤 담당자가 승인해야 발송 상태가 되는 업무 지원 도구를 만들어볼 수 있습니다.

### AI 솔루션·업무자동화 개발자의 실제 일

이번 자료를 기준으로 이 직무는 다음 흐름을 연결하는 사람으로 해석할 수 있습니다.

`현업 문제 파악 → 업무 단계와 예외 분석 → 데이터·API 연결 → AI와 규칙의 역할 분담 → 사람 승인 설계 → 정확도·보안 시험 → 로그·장애·변경 운영`

필요 역량은 크게 여섯 가지입니다.

- 업무 분석: 반복 작업, 판단 기준, 예외와 책임자를 찾아냅니다.
- 시스템 연결: DB, API, 문서, ERP와 기존 업무 도구를 연결합니다.
- AI 응용: 검색 기반 생성, 분류, 에이전트와 도구 호출을 알맞게 조합합니다.
- 품질 검증: 정확도뿐 아니라 근거, 실패 유형, 오탐과 사람 이관을 시험합니다.
- 보안·거버넌스: 권한, 민감정보, 로그, 승인과 책임 범위를 구현합니다.
- 운영: 장애 대응, 비용·속도 감시, 모델·문서·업무 규칙 변경을 관리합니다.

### 기존 경험을 살리는 추천 진입 방향

Java 운영·개발, 시스템 분석, 장애 대응, DB·API 연동과 운영 부서 협업 경험을 버리고 새로 시작할 필요는 없습니다. 가장 자연스러운 방향은 **기존 기업 시스템을 AI와 안전하게 연결하고 운영하는 개발자**입니다.

첫 포트폴리오로는 다음 순서를 권합니다.

1. 운영 문서를 근거로 답하는 Java 지식검색 API를 만듭니다.
2. 시스템 상태 조회나 티켓 초안 작성 도구를 연결합니다.
3. 민감정보·고위험 장애·낮은 확신도에서는 자동 실행을 멈추고 사람에게 넘깁니다.
4. 출처, 실행 내역, 승인자, 실패와 재시도를 로그로 남깁니다.
5. 답변 정확도뿐 아니라 처리 시간, 사람 이관률, 오탐과 복구 가능성을 함께 측정합니다.
