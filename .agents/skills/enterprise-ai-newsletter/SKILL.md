# Enterprise AI Newsletter

현재 제작 기준: v03(가독성 및 기존 검증 자료 재작성 개선)

## 목적

기업용 AI·업무자동화 사례를 통해 다음을 이해하도록 돕는 한국어 뉴스레터를 만든다.

- 기업이 해결하려는 업무 문제
- AI와 기존 시스템·데이터의 연결 방식
- 자동화 범위와 사람의 검토 지점
- 실제 성과와 근거
- AI 솔루션·업무자동화 개발자의 역할과 필요한 역량
- 사용자의 Java 운영개발 경험과 다음 학습 방향의 연결점
- 핵심 내용을 먼저 파악하고 자연스러운 흐름으로 읽을 수 있는 구성

이 스킬에서 말하는 직무는 기업의 업무 과정을 분석하고, 기존 시스템·데이터와 AI를 연결하여, 사람이 안전하게 확인할 수 있는 자동화 시스템을 만들고 운영하는 역할이다.

## 실행 경계

- 이 스킬은 사용자가 `$enterprise-ai-newsletter`로 명시적으로 호출할 때만 사용한다.
- 호출 후에도 사용자가 실행을 명시하지 않고 구성, 계획 또는 설명만 요청하면 인터넷 검색과 파일 생성을 하지 않는다.
- 사용자가 `실행시켜`라고 요청하면 `새 자료 수집`과 `기존 검증 자료 재작성` 중 어떤 방식인지 확인한다. 요청에서 방식이 분명하면 다시 선택하게 하지 않는다.
- 선택한 방식, 입력 자료, 검색 여부, 검색 기간, 목표 건수, 작성 방식과 예정 출력 경로를 먼저 보여주고 확인받는다. 확인 전에는 인터넷 검색이나 파일 생성을 하지 않는다.
- 이메일, Notion 등 외부 서비스로 보내거나 Git 커밋·푸시하지 않는다. 별도 요청과 확인이 있을 때만 해당 작업을 한다.
- 자동 실행이나 예약 실행은 현재 범위가 아니다.

## 기본 조건

- 관심 산업: 기업용 AI·업무자동화(Enterprise AI·AX)
- 관심 직무: AI 솔루션·업무자동화 개발자, AI Integration Engineer, Enterprise AI Solution Engineer
- 기간: 실행일을 끝으로 하는 최근 3개월. 90일이 아니라 달력의 3개월 전 같은 날짜부터 실행일까지를 포함한다.
- 언어: 결과는 한국어로 작성하며 해외 자료도 한국어로 요약한다.
- 수량: 총 7건을 목표로 한다.
- 지역 비중: 국내 5건, 해외 2건을 목표로 한다.
- 채용 공고와 일반적인 채용 소식은 제외한다.
- 기준을 충족하는 자료가 부족하면 약한 출처로 채우지 않고 실제 건수·비율과 부족 이유를 밝힌다.

## 실행 방식

### 1. 새 자료 수집

최신 자료가 필요하거나 검색 기간이 달라졌을 때 사용한다.

- 최근 3개월 자료를 새로 검색하고 원문을 검증한다.
- 검증 자료 묶음과 뉴스레터를 같은 실행 버전으로 각각 새 파일에 저장한다.
- [출처·선정 규칙](references/source-selection-rules.md)의 빠른 수집 절차를 따른다.
- 수집 시작과 검증 완료 시간을 기록해 실제 소요 시간을 보고한다.

### 2. 기존 검증 자료 재작성

이미 수집한 자료의 문체, 제목, 배치 또는 설명 방식만 바꿀 때 사용한다.

- 사용자가 지정하거나 가장 최근에 승인한 [검증 자료 묶음](references/research-pack-format.md)을 입력으로 사용한다.
- 인터넷 검색과 원문 재수집을 하지 않는다.
- 검증 자료 묶음을 사실의 기준으로 사용한다. 사용자가 특정 부분 보존을 요청하지 않았다면 기존 뉴스레터 문장을 다시 고치는 방식이 아니라 검증 자료에서 글을 새로 구성한다.
- 검증 자료에 없는 새 사실을 추가하거나 추측하지 않는다. 필요한 사실이 빠졌다면 부족함을 알리고 `새 자료 수집` 방식으로 바꿀지 확인한다.
- 원래 수집 기간과 원문 확인일을 그대로 표시한다. 현재 시점의 최신 뉴스라고 새로 주장하지 않는다.
- 기존 파일을 덮어쓰지 않고 뉴스레터만 다음 버전의 새 파일로 저장하며, 사용한 검증 자료 경로를 밝힌다.
- 재작성 시작과 완료 시간을 기록해 재작성 소요 시간을 보고한다.

## 실행 전 확인

사용자가 `실행시켜`라고 요청하면 다음을 한 번에 보여주고 진행 확인을 받는다.

1. 실행 방식: `새 자료 수집` 또는 `기존 검증 자료 재작성`
2. 인터넷 검색을 하는지 여부
3. 새 자료 수집이면 실행일, 기간의 시작일·종료일, 목표 7건과 국내 5건·해외 2건
4. 기존 자료 재작성이면 입력할 검증 자료 묶음의 정확한 경로와 원래 수집 기간
5. 적용할 문체, 기사별 예상 분량과 `4개 큰 영역 + 필수 질문 8개` 구조
6. 새로 만들 파일의 정확한 경로

프로젝트 결과는 다음 구조를 사용한다. `vNN`은 이미 존재하는 가장 높은 버전 다음의 비어 있는 번호다.

```text
projects/enterprise-ai-newsletter-2026-09-15-v01/newsletters/vNN/
├─ research-pack-YYYY-MM-DD-vNN.md   # 새 자료 수집일 때만 생성
└─ newsletter-YYYY-MM-DD-vNN.md
```

같은 이름이나 버전 폴더가 이미 있으면 덮어쓰지 않는다. 다음 번호와 정확한 파일 목록을 제안한 뒤 확인받는다.

## 새 자료 수집 절차

1. [출처·선정 규칙](references/source-selection-rules.md)을 읽는다.
2. 승인 직후 수집 시작 시간을 기록하고 최근 3개월 범위와 한국어·영어 검색어 묶음을 정한다.
3. 신뢰도가 높은 출처부터 국내·해외 검색어를 도구가 허용하는 범위에서 한 요청으로 묶어 검색한다.
4. URL 기준 후보 상태표를 유지하며 최종 7건과 예비 2건, 최대 9건까지만 후보로 남긴다.
5. 후보 원문은 가능한 한 묶어서 한 번씩 열고 발표일, 작성 주체, 출처 유형, 내용과 링크를 확인한다. 같은 URL은 필요한 정보가 빠졌거나 열기에 실패한 경우가 아니면 다시 열지 않는다.
6. 날짜나 핵심 성과 수치가 불명확하거나 자료끼리 충돌할 때만 보조 출처로 교차 확인한다.
7. 날짜 범위 밖 자료, 중복, 광고, 재게시물, 채용 소식과 출처 불명 자료를 제외하고 국내 5건·해외 2건을 선정한다.
8. 검증 완료 시간을 기록하고 [검증 자료 묶음 형식](references/research-pack-format.md)에 따라 먼저 저장한다.
9. [뉴스레터 형식](references/newsletter-format.md)을 읽고 검증 자료 묶음만을 근거로 `핵심 한 줄 + 4개 큰 영역 + 필수 질문 8개` 형식의 뉴스레터를 작성한다.
10. 모든 출처·날짜·링크, 실제 지역 비율, 중복 여부, 필수 분석 요소와 가독성 기준을 확인하고 소요 시간과 결과 경로를 보고한다.

## 기존 검증 자료 재작성 절차

1. 승인받은 검증 자료 묶음과 [뉴스레터 형식](references/newsletter-format.md)을 읽는다.
2. 입력 파일의 수집 기간, 원문 확인일, 선정 7건과 미확인 사항을 확인하고 재작성 시작 시간을 기록한다.
3. 검증 자료 묶음을 사실의 기준으로 삼아 글을 새로 구성한다. 사용자가 특정 부분의 보존을 요청했을 때만 기존 뉴스레터를 참고한다.
4. 각 자료를 `핵심 한 줄`, 간결한 기본 정보, 4개의 큰 분석 영역과 필수 질문 8개로 작성한다. 문체·제목·배치를 바꿔도 사실, 수치와 링크는 검증 자료 범위를 벗어나지 않는다.
5. 새 사실이 필요하면 인터넷이나 원문을 열지 않고 작업을 멈춰 `새 자료 수집` 전환 여부를 확인한다.
6. 다음 빈 버전의 뉴스레터 파일에 저장하고 사용한 검증 자료 경로, 원래 검색 기간·원문 확인일과 인터넷 검색을 하지 않았음을 표시한다.
7. 웹 검증 대신 로컬에서 자료 수, 출처 링크, 필수 질문 8개, 새로운 사실 추가 여부와 기존 파일 보존을 확인하고 재작성 완료 시간을 기록한다.
8. 재작성 소요 시간과 결과 경로를 보고한다.

## 필수 품질 기준

- 모든 자료에 제목, 발표일, 출처명과 원문 링크가 있어야 한다.
- 원문을 직접 확인하지 못한 자료는 포함하지 않는다.
- 링크는 검색 결과 페이지가 아니라 확인한 원문으로 연결한다.
- 공식 원문에서 제목, 날짜, 본문과 핵심 수치가 명확하면 그 원문을 기본 근거로 사용한다. 날짜나 성과 수치가 불명확하거나 자료끼리 충돌할 때만 보조 출처로 교차 확인한다.
- 기업 공식 자료는 `기업 공식 발표` 또는 `기업 공식 기술 콘텐츠`라고 표시한다.
- 기사에 개발자 역할이 직접 나오지 않으면 사실로 단정하지 않고 `직무 관점의 해석`으로 표시한다.
- 정보가 없으면 추측으로 채우지 않고 `확인되지 않음`이라고 쓴다.
- 긴 원문을 복사하지 않고 핵심을 자신의 말로 요약한다.
- 자료 하나를 여러 분야에 중복 게재하지 않고 대표 분야 하나에 배치한다.
- 같은 사실이나 성과 수치를 여러 분석 영역에서 반복하지 않는다.
- 전문용어는 처음 등장할 때 쉬운 말로 풀이하고 한 문단은 2~4문장을 기본으로 한다.

## 완료 보고

완료 시 다음을 짧게 보고한다.

- 실제 수집 기간
- 사용한 실행 방식과 인터넷 검색 여부
- 국내·해외 실제 건수와 비율
- 사용한 출처 유형
- 새 자료 수집이면 수집 시작부터 검증 완료까지 걸린 시간
- 기존 자료 재작성이면 사용한 검증 자료 묶음의 경로, 원문 확인일, 적용한 작성 방식과 재작성 소요 시간
- 저장한 파일의 절대 경로
- 자동 검사 또는 직접 확인한 항목
- 자료 부족, 링크 문제나 사람이 확인해야 할 내용

뉴스레터가 저장됐다는 사실과 내용의 정확성 검증을 구분해서 설명한다.
