# Enterprise AI Newsletter

현재 제작 기준: v01

## 목적

기업용 AI·업무자동화 사례를 통해 다음을 이해하도록 돕는 한국어 뉴스레터를 만든다.

- 기업이 해결하려는 업무 문제
- AI와 기존 시스템·데이터의 연결 방식
- 자동화 범위와 사람의 검토 지점
- 실제 성과와 근거
- AI 솔루션·업무자동화 개발자의 역할과 필요한 역량
- 사용자의 Java 운영개발 경험과 다음 학습 방향의 연결점

이 스킬에서 말하는 직무는 기업의 업무 과정을 분석하고, 기존 시스템·데이터와 AI를 연결하여, 사람이 안전하게 확인할 수 있는 자동화 시스템을 만들고 운영하는 역할이다.

## 실행 경계

- 이 스킬은 사용자가 `$enterprise-ai-newsletter`로 명시적으로 호출할 때만 사용한다.
- 호출 후에도 사용자가 실행을 명시하지 않고 구성, 계획 또는 설명만 요청하면 인터넷 검색과 파일 생성을 하지 않는다.
- 사용자가 `실행시켜`라고 요청하면 실행일, 검색 기간, 목표 7건과 예정 출력 경로를 먼저 보여주고 확인받는다. 확인 전에는 검색하거나 파일을 만들지 않는다.
- 이메일, Notion 등 외부 서비스로 보내거나 Git 커밋·푸시하지 않는다. 별도 요청과 확인이 있을 때만 해당 작업을 한다.
- 자동 실행이나 예약 실행은 v01 범위가 아니다.

## 기본 조건

- 관심 산업: 기업용 AI·업무자동화(Enterprise AI·AX)
- 관심 직무: AI 솔루션·업무자동화 개발자, AI Integration Engineer, Enterprise AI Solution Engineer
- 기간: 실행일을 끝으로 하는 최근 3개월. 90일이 아니라 달력의 3개월 전 같은 날짜부터 실행일까지를 포함한다.
- 언어: 결과는 한국어로 작성하며 해외 자료도 한국어로 요약한다.
- 수량: 총 7건을 목표로 한다.
- 지역 비중: 국내 5건, 해외 2건을 목표로 한다.
- 채용 공고와 일반적인 채용 소식은 제외한다.
- 기준을 충족하는 자료가 부족하면 약한 출처로 채우지 않고 실제 건수·비율과 부족 이유를 밝힌다.

## 실행 전 확인

사용자가 `실행시켜`라고 요청하면 다음을 한 번에 보여주고 진행 확인을 받는다.

1. 실행일과 포함되는 시작일·종료일
2. 목표 수량 7건과 국내 5건·해외 2건
3. 포함 분야와 제외 기준
4. 새로 만들 출력 파일 1개의 정확한 경로

기본 출력 위치는 다음과 같다.

`projects/enterprise-ai-newsletter-2026-09-15-v01/newsletters/v01/newsletter-YYYY-MM-DD-v01.md`

같은 이름이 이미 있으면 덮어쓰지 않는다. 존재 여부를 확인하고 `v02`, `v03`처럼 다음 번호의 새 파일을 제안한 뒤 확인받는다.

## 실행 절차

1. [출처·선정 규칙](references/source-selection-rules.md)을 읽는다.
2. 실행일 기준 최근 3개월 범위와 한국어·영어 검색어 묶음을 정한다.
3. 국내외 후보 자료를 목표 수량보다 넉넉하게 찾는다.
4. 후보의 원문을 열어 발표일, 작성 주체, 출처 유형, 내용과 링크를 확인한다.
5. 날짜 범위 밖 자료, 중복, 광고, 재게시물, 채용 소식과 출처 불명 자료를 제외한다.
6. 국내 5건·해외 2건을 목표로 선정하고 분야가 한쪽에 지나치게 몰리지 않았는지 확인한다.
7. [뉴스레터 형식](references/newsletter-format.md)을 읽고 각 자료를 필수 분석 제목 8개로 작성한다.
8. 확인된 사실, 자료를 바탕으로 한 해석, 아직 알 수 없는 내용을 구분한다.
9. 모든 출처·날짜·링크, 실제 지역 비율, 중복 여부와 8개 제목을 다시 확인한다.
10. 승인받은 새 파일에 저장하고 실제 건수·비율, 결과 경로, 제외 또는 미확인 사항을 보고한다.

## 필수 품질 기준

- 모든 자료에 제목, 발표일, 출처명과 원문 링크가 있어야 한다.
- 원문을 직접 확인하지 못한 자료는 포함하지 않는다.
- 링크는 검색 결과 페이지가 아니라 확인한 원문으로 연결한다.
- 핵심 수치와 중요한 주장은 가능하면 공식 자료 또는 서로 독립된 신뢰 가능한 자료로 교차 확인한다.
- 기업 공식 자료는 `기업 공식 발표` 또는 `기업 공식 기술 콘텐츠`라고 표시한다.
- 기사에 개발자 역할이 직접 나오지 않으면 사실로 단정하지 않고 `자료를 바탕으로 한 해석`으로 표시한다.
- 정보가 없으면 추측으로 채우지 않고 `아직 알 수 없는 내용`이라고 쓴다.
- 긴 원문을 복사하지 않고 핵심을 자신의 말로 요약한다.
- 자료 하나를 여러 분야에 중복 게재하지 않고 대표 분야 하나에 배치한다.

## 완료 보고

완료 시 다음을 짧게 보고한다.

- 실제 수집 기간
- 국내·해외 실제 건수와 비율
- 사용한 출처 유형
- 저장한 파일의 절대 경로
- 자동 검사 또는 직접 확인한 항목
- 자료 부족, 링크 문제나 사람이 확인해야 할 내용

뉴스레터가 저장됐다는 사실과 내용의 정확성 검증을 구분해서 설명한다.
