# Enterprise AI Newsletter

현재 제작 기준: 직무 분석 2개 + 재미 중심 읽을거리 2개 + 생각 정리 연습 1개. 짧은 본문과 펼치기·접기로 읽는 깊이를 선택한다.

## 목적

기업용 AI·업무자동화 사례를 통해 업무 문제, 시스템·데이터 연결, 사람의 검토 지점, 성과 근거와 개발자 역할을 이해하도록 돕는다. 사용자의 Java 운영개발, 시스템 분석, 장애 대응, 데이터베이스·API 연결과 운영 부서 협업 경험을 다음 학습과 연결한다.

재미있는 AI 이야기로 쉬어 가고, 원하는 결과·조건·판단 기준을 말로 정리하는 연습을 제공한다. 논리적 사고나 프롬프트 능력의 향상 효과를 검증 없이 보장하지 않는다.

## 실행 경계

- 사용자가 `$enterprise-ai-newsletter`로 명시적으로 호출할 때만 사용한다. 실행이 아닌 구성·계획·설명 요청에는 검색이나 파일 생성을 하지 않는다.
- **규칙 수정, 자료 조사, 뉴스레터 제작은 구분한다.** 규칙을 수정하라는 요청을 새 자료 조사나 새 뉴스레터 생성 요청으로 확대하지 않는다.
- 실행 방식은 `새 자료 수집` / `기존 검증 자료 재작성`, 출력 범위는 `자료 조사·출처 검증만` / `뉴스레터까지`로 구분한다. 요청에 명시된 선택은 다시 묻지 않는다.
- 사용자가 자료만 요청하면 검증 자료 묶음만 저장한 뒤 종료한다. 자료를 확인했다는 말이나 선호 방향에 대한 동의를 뉴스레터 제작 요청으로 간주하지 않는다. 별도 제작 요청을 기다린다.
- 실행 방식, 입력, 검색 여부·기간, 구성과 정확한 새 파일 경로를 먼저 안내한다. 이미 명시적으로 승인받은 범위는 재확인하지 않는다. 새 버전 경로·생성에 별도 동의가 필요한 경우 작업 공간의 보존 규칙을 따른다.
- 이메일·Notion 등 외부 전송, Git 커밋·푸시, 예약 실행은 별도 요청 없이 하지 않는다.

## 기본 조건

- 관심 산업: 기업용 AI·업무자동화. 관심 직무: 기업 업무를 분석하고 기존 시스템·데이터와 AI를 연결해 자동화 시스템을 만들고 운영하는 개발자.
- 언어: 친근한 한국어. 전문용어는 처음 나올 때 쉬운 말로 설명한다.
- 뉴스 원문: 실행일부터 달력 기준 3개월 전 같은 날짜까지 포함한다. 90일로 계산하지 않는다.
- 구성: **직무·산업 분석 2개 + 엉뚱한 AI 실험 1개 + 웃기고 공감되는 이야기 1개 + 생각 정리 연습 1개**, 총 5개 코너.
- 뉴스 원문은 4건이다. 같은 원문을 두 기사로 세지 않는다. 연습 1개와 연습의 참고 자료는 뉴스 건수·국내외 비율·출처 유형 집계에서 분리한다.
- 뉴스 4건은 국내 중심으로 해외 관점도 포함하되 고정 할당을 강제하지 않는다. 실제 건수와 비율을 표시한다.
- 가벼운 글은 기술·제품 소개보다 엉뚱함과 일상 공감을 우선하되, 사실·출처 검증 기준은 유지한다.
- 생각 정리 연습은 목표 구체화, 사실과 추측 구분, 비교 기준 세우기, 빠진 조건 찾기 중 한 가지에 집중한다. 개념 참고 자료에는 최근 3개월 제한을 적용하지 않되 원래 발표일·확인일을 기록한다. 최근 사건을 소재로 사용한다면 뉴스와 같은 기간·검증 기준을 적용한다.
- 출력은 스타일을 포함한 단일 HTML, 검증 자료 묶음은 Markdown이다. 분석의 짧은 본문은 먼저 보이고, 4개 영역·질문 8개의 상세 답은 `더 읽기` 아래에 접어 둔다.
- 자료가 부족하면 기준을 낮춰 채우지 않고 실제 구성과 부족 이유를 밝힌다. 채용 공고와 채용 소식은 제외한다.

## 1. 새 자료 수집

1. [출처·선정 규칙](references/source-selection-rules.md)을 읽고 요청된 출력 범위와 예정 경로를 확인한다.
2. 수집 시작 시간을 기록한다. 최근 3개월의 국내·해외 검색어를 최대 4개까지 묶어 검색한다.
3. URL 기준 후보 상태표를 유지한다. 뉴스 최종 4건 + 예비 최대 2건, 최대 6건을 후보로 남긴다. 연습의 개념 참고 자료는 별도로 1건을 목표로 한다.
4. 후보 원문을 가능한 한 묶어서 한 번씩 열어 발표일, 작성 주체, 출처 유형, 사실·핵심 수치와 링크를 검증한다. 누락·열기 실패 외에는 같은 URL을 재확인하지 않는다. 날짜·수치가 모호하거나 충돌할 때만 보조 출처를 추가한다.
5. 직무 2건과 두 재미 유형을 각각 선정한다. 읽을거리의 재미 포인트를 한 문장으로 설명할 수 있어야 한다. 부족한 코너와 연습 참고 자료는 보충 검색 한 번에 함께 찾고, 이후 부족함을 보고한다.
6. 생각 정리 연습을 위한 참고 개념, 출처, 연습 목표와 소재를 별도 기록한다. 직접 만든 상황은 가상 상황으로 표시하고 실제 사례처럼 제시하지 않는다.
7. 검증 완료 시간을 기록하고 [검증 자료 묶음 형식](references/research-pack-format.md)에 따라 새 파일로 저장한다.
8. **자료 조사·출처 검증만 요청받았다면 여기서 종료한다.** 뉴스레터 본문·완성 연습 문제·HTML을 작성하지 않는다.
9. 뉴스레터 제작까지 요청받은 경우에만 [뉴스레터 형식](references/newsletter-format.md)에 따라 검증 자료를 근거로 HTML을 만든다.
10. 구성·출처·날짜·사실과 해석 구분, 상세 분석의 누락, 가독성과 펼치기·접기를 확인해 보고한다.

## 2. 기존 검증 자료 재작성

1. 사용자가 지정하거나 가장 최근 승인한 검증 자료 묶음과 [뉴스레터 형식](references/newsletter-format.md)을 읽는다.
2. 인터넷 검색·원문 재수집은 하지 않는다. 원래 수집 기간, 원문 확인일, 미확인 사항을 유지하며 현재 시점의 최신 정보라고 주장하지 않는다.
3. 기존 자료에서 직무 2건과 두 재미 유형의 읽을거리 각 1건을 고른다. 기술 해설을 억지로 재미있는 실험·후기로 바꾸거나 원문에 없는 웃긴 결과를 만들지 않는다.
4. 생각 정리 연습은 검증 묶음의 별도 참고 개념을 바탕으로 가상 상황·질문·생각의 예시를 구성한다. 검증 자료에 없는 새로운 사실·효과 주장을 추가하지 않는다.
5. 적합한 재미 소재나 연습 참고 자료가 없으면 부족함을 알린다. 이미 허용되지 않은 새 자료 수집이 필요할 때만 전환 여부를 확인한다.
6. 재작성 시작 시각을 기록하고 검증 자료에서 글을 새로 구성한다. 보존을 요청받은 부분에만 기존 뉴스레터를 참고한다.
7. 새 HTML을 다음 빈 버전에 저장한다. 입력 검증 자료의 상대 링크와 원래 기간·원문 확인일을 표시한다. `인터넷 검색·원문 재확인: 하지 않음` 항목은 HTML에서 생략하고 작업일지·완료 보고에만 남긴다.
8. 로컬에서 뉴스 4건·연습 1개, 출처·링크, 분석별 질문 8개, 사실 추가 여부와 기존 파일 보존을 확인한다. 화면·클릭·키보드 확인은 별도 검증으로 구분하고 완료 시간을 기록한다.

## 저장 경로

프로젝트 결과는 아래 구조를 사용한다. `vNN`은 이미 존재하는 가장 높은 실행 버전 다음의 빈 번호다. 기존 파일을 덮어쓰거나 입력 검증 자료를 고치지 않는다.

```text
projects/enterprise-ai-newsletter-2026-09-15-v01/newsletters/vNN/
├─ research-pack-YYYY-MM-DD-vNN.md   # 새 자료 수집 결과
└─ newsletter-YYYY-MM-DD-vNN.html   # 별도 제작 요청 또는 제작까지 승인된 경우
```

자료만 요청했다면 Markdown 한 파일, 기존 자료 재작성이라면 HTML 한 파일만 만든다. 충돌 시 다음 빈 번호와 정확한 파일 목록을 안내하고 작업 공간의 버전 생성 규칙을 따른다.

## 필수 품질 기준과 완료 보고

- 뉴스마다 제목·발표일·출처명·직접 확인한 원문 링크를 제공한다. 검색 결과·원문 미확인 자료는 포함하지 않는다.
- 기업 공식 자료의 성과는 기업 주장으로, 원문에 없는 개발자 역할은 `직무 관점의 해석`으로, 모르는 정보는 `확인되지 않음`으로 구분한다.
- 원문을 길게 복사하지 않으며, 같은 사실·성과 수치를 여러 영역에 반복하지 않는다. 요약에서도 핵심 한계와 출처를 숨기지 않는다.
- 실제 기간, 실행 방식과 검색 여부, 뉴스의 국내외·출처 유형별 건수, 연습 참고 자료, 수집 또는 재작성 소요 시간, 입력·출력의 절대 경로를 짧게 보고한다.
- 파일 검사, 브라우저 화면 확인, 클릭·키보드 동작 확인, 사용자 직접 확인을 구분한다. 실제로 하지 않은 검증을 완료로 표현하지 않는다.
- 자료 조사만 마쳤다면 `검증 자료만 저장, 뉴스레터 미제작`이라고 명시한다. 규칙 수정만 했다면 새 결과물 제작 완료로 표현하지 않는다.
