# 검증 자료 묶음 형식

검증 자료 묶음은 새 자료 수집 결과를 뉴스레터 작성과 이후 재작성에 재사용하기 위한 중간 기록이다. 원문을 대신하는 영구 자료가 아니며, 확인한 사실과 확인하지 못한 내용을 빠뜨리지 않는 데 목적이 있다. 뉴스레터의 문체나 화면 구조를 정하는 서식이 아니라 재작성에서 사실의 기준이 되는 자료다.

## 1. 머리말

다음 정보를 기록한다.

- 수집 실행일과 원문 확인일
- 검색 기간의 시작일과 종료일
- 목표 및 실제 뉴스 자료 수 (직무 2건 + 재미 읽을거리 2건)와 별도의 연습 참고 자료 수
- 뉴스 자료만을 기준으로 한 국내·해외 실제 건수·비율
- 수집 시작 시각, 검증 완료 시각과 소요 시간
- 뉴스의 출처 유형별 건수 (연습 참고 자료는 별도 기록)
- 검색 횟수와 보충 검색 여부
- 자료 부족 또는 사람이 확인해야 할 사항

## 2. 선정 뉴스 자료 4건 (분석 2건 + 읽을거리 2건)

각 자료에 다음 항목을 작성한다.

```markdown
## [번호]. [자료 제목]

- 상태: 선정
- 코너: 직무 분석 / 엉뚱한 AI 실험 / 웃기고 공감되는 이야기
- 대표 분야:
- 국내·해외:
- 출처 유형:
- 출처명:
- 발표일:
- 원문 확인일:
- 원문: [원문 보기](https://example.com)
- 보조 출처: 없음 또는 사용한 링크와 확인 이유
- 선정 이유:
- 재미 포인트: 읽을거리일 때 원문에서 확인된 엉뚱함 또는 공감되는 지점을 한 문장으로 기록

### 확인된 사실

### 해결하려는 업무 문제

### 연결된 시스템·데이터

### 자동화 범위와 사람의 확인 지점

### 성과 수치와 근거 수준

### 개발자 역할에 대한 해석

### 기존 경험과의 연결

### 학습·실습 아이디어

### 아직 알 수 없는 내용
```

분석 자료에는 위 항목을 모두 기록한다. 읽을거리는 출처·날짜·확인된 사실·근거 수준·미확인 사항을 유지하고, 나머지는 관련된 경우에 기록한다. 이야기의 관점과 직접 해보기 제안은 사실과 구분한다. 같은 원문을 두 콘텐츠로 세지 않는다.

성과 수치는 `공공·연구 근거`, `기업·고객 공동 발표`, `기업 단독 주장`, `독립 언론 보도`, `근거 없음` 중 알맞은 근거 수준을 함께 표시한다.

## 3. 생각 정리 연습용 참고 자료 (뉴스 집계에서 제외)

아래 내용을 별도 기록한다. 자료 조사만 요청받은 단계에서는 완성된 연습 문제·예시 답안·뉴스레터 본문을 작성하지 않는다.

```markdown
## 생각 정리 연습 준비

- 상태: 참고 자료 확인 / 자료 부족
- 연습 목표: 목표 구체화 / 사실과 추측 구분 / 비교 기준 세우기 / 빠진 조건 찾기 중 하나
- 참고 개념:
- 출처명·작성 주체:
- 원문: [참고 자료](https://example.com)
- 원래 발표·수정일: 날짜가 없으면 미표기라고 기록
- 원문 확인일:
- 원문에서 확인한 설명:
- 연습으로 연결할 소재 메모:
- 상황의 성격: 작성 예정인 가상 상황 / 검증한 실제 사건
- 실제 사건의 근거: 해당하는 경우 검증한 뉴스 번호·발표일·출처 연결
- 아직 알 수 없는 내용·적용 한계:
```

개념 참고 자료에는 최근 3개월 조건을 적용하지 않는다. 최근 사건을 연습 소재로 사용하면 뉴스와 같은 기간·원문 검증 기준을 적용한다. 같은 뉴스를 참고해도 원문 건수·지역 비율을 중복 계산하지 않는다. 참고 출처가 만든 문제나 효과가 검증된 훈련인 것처럼 표현하지 않는다.

## 4. 예비 뉴스 자료 최대 2건

예비 자료에도 제목, 지역, 출처 유형, 발표일, 원문 링크, 원문 확인일, 선정하지 않은 이유와 대체 가능한 대표 분야를 기록한다. 이후 선정 자료를 교체해야 할 때 원문을 불필요하게 다시 찾지 않기 위한 정보다.

## 5. 재작성 사용 규칙

- 문체, 제목, 순서, 출력 형식과 설명 방식을 바꾸거나 기존 자료 중 4건을 골라 분석 2개·재미 읽을거리 2개로 재구성하고 별도의 연습 참고 자료를 사용할 때는 인터넷 검색 없이 재사용할 수 있다.
- 재작성 시작과 완료 시간을 기록하고 실제 재작성 소요 시간을 보고한다.
- 사용자가 특정 부분의 보존을 요청하지 않았다면 기존 뉴스레터를 고쳐 쓰지 않고 검증 자료 묶음에서 글을 새로 구성한다.
- 재작성 전 적용할 문체, 기사별 예상 분량, 분석 2개에는 `짧은 본문 + 더 읽기 안의 4개 영역·질문 8개`, 읽을거리 2개에는 짧은 재미 이야기, 연습 1개에는 `상황·질문 + 접힌 생각의 예시` 및 새 출력 경로를 먼저 안내한다. 이미 승인받은 범위를 다시 묻지 않으며, 새 버전 생성은 작업 공간의 보존 규칙을 따른다.
- 재작성한 뉴스레터에는 사용한 검증 자료 묶음의 경로, 원래 검색 기간과 원문 확인일을 표시한다.
- 검증 자료에 없는 새로운 사실이나 수치를 만들지 않는다. 두 재미 유형에 맞는 소재 또는 연습 참고 자료가 기존 묶음에 없으면 부족함을 알리고 새 자료 수집이 허용됐는지 확인한다. 기술 해설을 실제 엉뚱한 실험이나 웃긴 사용 경험으로 꾸미지 않는다.
- 사용자가 현재 시점의 최신 자료, 다른 검색 기간 또는 새로운 사례를 원하면 재사용하지 않고 `새 자료 수집` 방식을 제안한다.
- 필요한 핵심 정보가 빠졌으면 `확인되지 않음`으로 유지하거나 사용자에게 새 자료 수집 전환 여부를 확인한다.
- 검증 자료 묶음 자체를 수정하지 않는다. 원문을 다시 확인해 사실을 보완해야 하면 새 실행 버전으로 수집한다.
- 재작성 검증은 웹 확인 대신 로컬에서 자료 수, 출처 링크, 분석별 필수 질문 8개와 두 재미 유형·별도 연습의 구성, 검증 자료 밖의 새로운 사실 추가 여부와 기존 파일 보존을 확인한다.

- 재작성 결과는 HTML로 저장하되 입력 검증 자료는 Markdown 그대로 보존한다. 최종 화면에서 검색 미실시 항목만 생략하며 내부 검색 금지 규칙은 유지한다.


## 6. 자료 조사만 요청받은 경우 완료 조건

- 검증한 뉴스 4건과 연습 참고 자료·소재 메모를 하나의 Markdown 묶음에 저장한다. 부족하면 실제 건수와 이유를 기록한다.
- 수집한 사실과 미확인 사항은 요약 과정에서 삭제하지 않는다. 본문 축약과 펼치기·접기 규칙은 최종 HTML에 적용하며 이 검증 묶음에는 적용하지 않는다.
- 뉴스레터 본문·완성 연습 문제·HTML을 만들지 않는다. 사용자에게 자료를 확인할 경로를 제공하고 별도 제작 요청을 기다린다.
