# 검증 자료 묶음 형식

검증 자료 묶음은 새 자료 수집 결과를 뉴스레터 작성과 이후 재작성에 재사용하기 위한 중간 기록이다. 원문을 대신하는 영구 자료가 아니며, 확인한 사실과 확인하지 못한 내용을 빠뜨리지 않는 데 목적이 있다. 뉴스레터의 문체나 화면 구조를 정하는 서식이 아니라 재작성에서 사실의 기준이 되는 자료다.

## 1. 머리말

다음 정보를 기록한다.

- 수집 실행일과 원문 확인일
- 검색 기간의 시작일과 종료일
- 목표 및 실제 자료 수
- 국내·해외 실제 건수
- 수집 시작 시각, 검증 완료 시각과 소요 시간
- 출처 유형별 건수
- 검색 횟수와 보충 검색 여부
- 자료 부족 또는 사람이 확인해야 할 사항

## 2. 선정 자료 7건

각 자료에 다음 항목을 작성한다.

```markdown
## [번호]. [자료 제목]

- 상태: 선정
- 대표 분야:
- 국내·해외:
- 출처 유형:
- 출처명:
- 발표일:
- 원문 확인일:
- 원문: [원문 보기](https://example.com)
- 보조 출처: 없음 또는 사용한 링크와 확인 이유
- 선정 이유:

### 확인된 사실

### 해결하려는 업무 문제

### 연결된 시스템·데이터

### 자동화 범위와 사람의 확인 지점

### 성과 수치와 근거 수준

### 개발자 역할에 대한 해석

### 기존 경험과의 연결

### 학습·실습 아이디어

### 아직 알 수 없는 내용
```

성과 수치는 `공공·연구 근거`, `기업·고객 공동 발표`, `기업 단독 주장`, `독립 언론 보도`, `근거 없음` 중 알맞은 근거 수준을 함께 표시한다.

## 3. 예비 자료 최대 2건

예비 자료에도 제목, 지역, 출처 유형, 발표일, 원문 링크, 원문 확인일, 선정하지 않은 이유와 대체 가능한 대표 분야를 기록한다. 이후 선정 자료를 교체해야 할 때 원문을 불필요하게 다시 찾지 않기 위한 정보다.

## 4. 재작성 사용 규칙

- 문체, 제목, 순서와 설명 방식만 바꿀 때는 인터넷 검색 없이 재사용할 수 있다.
- 재작성 시작과 완료 시간을 기록하고 실제 재작성 소요 시간을 보고한다.
- 사용자가 특정 부분의 보존을 요청하지 않았다면 기존 뉴스레터를 고쳐 쓰지 않고 검증 자료 묶음에서 글을 새로 구성한다.
- 재작성 전 적용할 문체, 기사별 예상 분량, `4개 큰 영역 + 필수 질문 8개` 구조와 새 출력 경로를 보여주고 확인받는다.
- 재작성한 뉴스레터에는 사용한 검증 자료 묶음의 경로, 원래 검색 기간과 원문 확인일을 표시한다.
- 검증 자료에 없는 새로운 사실이나 수치를 만들지 않는다.
- 사용자가 현재 시점의 최신 자료, 다른 검색 기간 또는 새로운 사례를 원하면 재사용하지 않고 `새 자료 수집` 방식을 제안한다.
- 필요한 핵심 정보가 빠졌으면 `확인되지 않음`으로 유지하거나 사용자에게 새 자료 수집 전환 여부를 확인한다.
- 검증 자료 묶음 자체를 수정하지 않는다. 원문을 다시 확인해 사실을 보완해야 하면 새 실행 버전으로 수집한다.
- 재작성 검증은 웹 확인 대신 로컬에서 자료 수, 출처 링크, 필수 질문 8개, 검증 자료 밖의 새로운 사실 추가 여부와 기존 파일 보존을 확인한다.
